# T11. Animated diagrams as components

## Goal

Port the inline-script diagrams from Webflow embeds to components selected by key.

## Inputs

- migration/contracts/blocks.json diagramKeys
- migration/00-inventory/live-site/html/
- migration/00-inventory/webflow/page-content/

## Steps

1. Find every diagram embed in the live HTML; extend the key list via a contract request if there are more than in blocks.json.
2. One component per key, no global ids, `prefers-reduced-motion` respected (skills `animate`, `animation-performance`).

## Done when

- [x] Every key renders on `/_ds/diagrams` (noindex).
- [x] No layout shift (CLS 0) when diagrams mount.

## Handoff

### What changed

- The live site has **52** animated diagrams on 13 pages, not 11. Each key maps to exactly one embed, even when several pages carry it (`zw-problem` is on 4 pages, `zw-step1` on 3). `registry.ts` lists every key with the pages it came from.
- `apps/web/src/components/diagrams/<Key>.astro` holds one component per key (`zw-manual-relay` → `ZwManualRelay.astro`). Each one is the original embed with four mechanical changes. The root `id` becomes `class="dg" data-diagram="<key>"`. CSS `#<key>` becomes `[data-diagram="<key>"]`. The script runs once per instance (`for (const root of querySelectorAll(...))`) instead of `getElementById`. The JS `fit()` is now a no-op. Markup, scene CSS, timing and easing are otherwise verbatim. The design comment from each embed moved into the component frontmatter, so it doesn't ship.
- `diagram.css` replaces the JS `fit()`. Each root carries `--dg-w` (design width) and `--dg-h` (measured scene height). `.dg-stage` is an inline-size container. `.dg-fit` reserves `min(h, 100cqi·h/w)` and scales with `min(1, tan(atan2(100cqi, w)))`. The final height is in place before any script runs, which is what gives CLS 0. The same file pins the inherited Webflow body text (16px / 1.75 / -0.011em). It also undoes three site reset rules inside `.dg` that changed wrapping and shrinking (`min-width: 0` on `*`, inherited `text-wrap: pretty`, `svg { display: block }`) and restores the Webflow `li` margin `ai-sales` depends on.
- `Diagram.astro` takes `diagram: DiagramKey` and renders the matching component. This is the selector a `contentSection` block with `media.kind = 'diagram'` should use.
- `pages/_ds/diagrams.astro` renders every key twice: in a wide slot and in a 320px slot. Rendering twice also proves that two instances on one page work.
- `components/diagrams/port/` holds the levers. `port-diagrams.mjs` regenerates every component and `registry.ts` from the inventory. `--check` fails if any committed file is stale. `measure-diagrams.mjs` writes `sizes.json` from the running page. `parity-diagrams.mjs` renders the original embeds with the live Webflow CSS and the port side by side, and compares every scene element's box and opacity, first with reduced motion and then after playing. `layout-diagrams.mjs` checks reserved heights, slot overflow and CLS at 375 and 1280. All of them need the inventory and a `verify-web` instance.

### Deviations

- `apps/web/src/pages/[ds]/diagrams.astro` is outside `owns`. Astro never routes files under an underscore folder, so `pages/_ds/diagrams.astro` alone builds no page. The 9-line route renders it at `/_ds/diagrams`. T09 and T10 hit the same wall for `/_ds/blocks-a` and `/_ds/blocks-b`. They can add `[ds]/blocks-a.astro` and so on next to it.
- Contract request: extend `blocks.json` `diagramKeys.keys` to the 52 keys in `apps/web/src/components/diagrams/registry.ts` (`diagramKeys`). The 11 keys in the contract are all among them. This task does not own the contract and does not change it.
- Colours stay as the embeds' own hex `--zw-*` / `--cf-*` variables. Swapping them for site tokens is a refinement that parity can't check, so it stays out of this port.
- No subagent. The work was one generator plus measuring, so I kept it in one context.

### Follow-ups

- Production `/_ds/*` gets the `<meta name="robots" content="noindex">` but no `X-Robots-Tag`, because the Worker only adds that header on non-production hosts. T13 should keep `/_ds/*` out of the sitemap. The Worker owner could add the header for `/_ds/` on every host.
- `verify-web doctor` reports `dist` as stale whenever a file under `src/` is newer, and that includes the Node tools in `diagrams/port/`. Rebuilding clears it. The check could skip `*.mjs`.
- If the site body font or the Satoshi files change, rerun `measure-diagrams.mjs`, `port-diagrams.mjs` and `parity-diagrams.mjs`.
