# T73. Weekly scheduled Sanity backup to Backblaze B2

## Goal

T64 added `migration/tools/backup-sanity.mjs` and uploaded the first encrypted Restic bundle to private Backblaze B2 by hand. Nothing runs it on a schedule, and without a read token the export holds published content only.

Run the backup automatically once a week (the owner changed the T64 plan from daily to weekly on 2026-11-12), including drafts and assets, and store each verified bundle in B2 under Object Lock.

## Steps

1. Create a dedicated Sanity API token with the `viewer` role (reads drafts and assets) and store it only as the GitHub Actions secret `SANITY_BACKUP_READ_TOKEN`. Store the B2 key and the Sanity Restic password from 1Password as Actions secrets. Creating a token and secrets is a human-gated step: the owner approved it on 2026-11-12.
2. Add `.github/workflows/backup-sanity.yml`: weekly at Sunday 04:15 `Europe/Warsaw`, plus manual dispatch. Run the T64 export with drafts, pack it into a standalone Restic repository, check it with `--read-data`, upload the `.restic.tar` bundle with 30-day Compliance Object Lock, and confirm the B2 checksum. The repo is public, so logs show only counts, checksums and object names.
3. Update `RESTORE.md` for the weekly schedule and retention.
4. Run the workflow once by hand and record the evidence.

## Done when

- [ ] A manual run of the workflow produced a bundle in B2 with `drafts_included=true`, Object Lock, and a matching checksum.
- [ ] The schedule is weekly at 04:15 Europe/Warsaw.
- [ ] No secret value appears in the repo or in the workflow log.
- [ ] `tasks.py check` passes; PR opened with status `review`.
