# T60. CI: run the tests, pin Node, tighten the workflow

## Goal

The 2026-11-12 comparison with the `nowa-strona-ola` repo (same stack, longer in use) found that CI here never runs the tests. `ci.yml` runs `pnpm check`, `tsc`, `pnpm build` and `tasks.py check`. The repo has 34 test files (`apps/web/src/**/*.test.{ts,mjs}`, run with `node --test`), and the T31 handoff records that a literal `node --test src` fails under Node 24. Nobody would notice a red test today.

Make CI the single gate: a PR is green only when types, tests and the build pass on the pinned Node version.

## Steps

1. Run `pnpm --filter web test` and `pnpm --filter web preview:test` locally on Node 24. Record what passes and what fails in `migration/lanes/platform/out/t60-ci/`.
2. If tests fail because of the test files themselves, fix them. Add each file you must touch to `owns` in the PR and say why. Do not skip or delete a test to get green. If a failure needs a file owned by an active task, record it under Handoff and leave that one test out of CI by name, with a comment that names the follow-up.
3. Add a root `test` script (`pnpm -r --if-present test`) and run it in CI after `check`. Include the preview tests.
4. Pin Node. Add `.node-version` with `24`. Use `node-version-file` in CI. Set `engines.node` to `>=24 <25` in the root and web `package.json`, and `engine-strict=true` in `.npmrc`. Workers Builds already sets `NODE_VERSION=24`; do not change that setting.
5. Tighten the workflow: `permissions: contents: read`, `timeout-minutes` on the job, and a `concurrency` group that cancels superseded runs on the same PR.
