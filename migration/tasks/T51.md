## Loosen schema false positives

Do not "fix" imported content that already works on the site. Change the schema, and only adjust `ContentSection.astro` / `Pricing.astro` if optional fields would otherwise break the page.

- **`contentItem.text` required (93 errors, 13 pages).** Checklist/card items often have only a title. Make `text` optional.
- **Empty headings (6 required + 6 `/\S/` mismatches).** Some sections, including T42 CTA bands (`t42-band`), have an empty heading. Do not weaken `headingField` globally if that would make a hero heading optional. Inspect which block types are empty and loosen only those (for example a local optional heading on `ctaBand` / the affected type).
- **Plan `price` required and `min(0)` (9 + 9 errors, 8 pages).** Prices are missing or unusable for "on request" plans. Make `price` optional; keep `priceNote`. The page must still render a plan with no numeric price.
- **Plan `features` required (2 errors, 1 page).** Make the list optional.
- **`contentItem` title max 160 (1 error).** `titleField` is shared. Do not shorten that item's content. Raise or scope the limit so this imported title is valid, without touching SEO limits.
- **Diagram registry.** `migration/contracts/blocks.json` `diagramKeys.keys` still has only 11 keys. `apps/studio/schemaTypes/objects.ts` validates `media.key` against that list, so Studio flags keys that already exist in `apps/web/src/components/diagrams/registry.ts` and in published content (51 `custom` errors + 51 `value.not-allowed` + 51 "Wybierz diagram." warnings). Sync the contract list from the web registry (the diagrams are already implemented). Only touch `registry.ts` if a content key is truly missing there; if you must, add that file to `owns` in the PR and say why. Do not invent placeholder diagram components.

After the schema changes (and with the unapplied SEO dry-run not yet written), `sanity documents validate` should be clean of these false positives. SEO max-length errors remain until the write is approved and applied. Record the before/after counts in the evidence dir.
