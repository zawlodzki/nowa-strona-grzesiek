# T26. Consent loader in the document head

## Goal

Put the c15t loader and the Consent Mode default into every page, early in `<head>`, so a later T21 pass can see them. This task does not deploy.

T27 depends on this task. Mount `<Header />` and `<Footer />` in `Base.astro`, and leave the two component files as empty landmarks. T27 owns `apps/web/src/components/site/**` and replaces those landmarks. T27's `owns` glob covers those two files. That overlap is safe because T27 cannot be claimed until this task is done, and `tasks.py` only rejects an overlap when both tasks are claimed or in review.

A named slot would push the chrome into the route files under `apps/web/src/lib/sanity/**`. T20 still owns that tree. The mount stays in `Base.astro`.

## Inputs

- `migration/lanes/tracking/out/consent-qa.md`, heading "Sprawdź kolejność inicjalizacji"
- `AGENTS.md`, the Consent rule
- The public homepage `https://www.zawlodzki.pl/`, read on 2026-10-23
- PR #35. Staging already serves the imported site, and the HTML still has no loader. The gap is this layout file.

## Steps

1. In `apps/web/src/layouts/Base.astro`, immediately after the charset and viewport metas and before the font preloads, emit the block below. Do not add a `googletagmanager.com/gtm.js` tag. The loader starts GTM. If Astro rewrites a `<script>`, add `is:inline` so the id, the signals, and the loader `src` stay in the server HTML.

```html
<script id="zawlodzki-consent-default">
  window.dataLayer = window.dataLayer || [];
  window.gtag = window.gtag || function () {
    window.dataLayer.push(arguments);
  };
  window.gtag('consent', 'default', {
    security_storage: 'granted',
    analytics_storage: 'denied',
    ad_storage: 'denied',
    ad_user_data: 'denied',
    ad_personalization: 'denied'
  });
</script>
<link rel="preconnect" href="https://consent.zawlodzki.com" crossorigin>
<script defer src="https://consent.zawlodzki.com/assets/cmp-v1.js?v=20260821-1"></script>
```

2. In the same file, wrap the existing `<slot />` and pass the page language and path. Import the components from `../components/site/Header.astro` and `../components/site/Footer.astro`.

```astro
<Header language={props.seo?.language ?? 'pl'} pathname={Astro.url.pathname} />
<slot />
<Footer language={props.seo?.language ?? 'pl'} pathname={Astro.url.pathname} />
```

3. Create the two files as empty landmarks so the imports resolve. `Header.astro` renders `<header>` and nothing else. `Footer.astro` renders `<footer>` and nothing else. No links, no CSS, no `data-c15t-open`, and no Sanity query. Do not edit `apps/web/src/lib/sanity/**`.

### Zmiany

`apps/web/src/layouts/Base.astro` wstawia blok z tego zadania zaraz po meta viewport i przed preloadem fontów. Oba skrypty mają w źródle `is:inline`. Astro 7.4.1 zdejmuje dyrektywę z odpowiedzi i zostawia `id`, pięć sygnałów, `defer` oraz adres loadera. `language` jest wyliczane raz, jako `Language` z `props.seo`. Przy braku `seo` wartość to `pl`. `pathname` to `Astro.url.pathname`.

`apps/web/src/components/site/Header.astro` renderuje pusty `<header>`. `Footer.astro` renderuje pusty `<footer>`. Oba deklarują lokalnie `language: 'pl' | 'en'` i `pathname: string`. Nie importują typów SEO. Nie ma linków, CSS, zapytania Sanity ani `data-c15t-open`.

### Odchylenia

`is:inline` jest w źródle, bo goły `<script>` w tym Astro idzie do bundlera. Bez dyrektywy `id` i adres loadera zniknęłyby z HTML. W odpowiedzi dyrektywy nie ma.

W dokumencie jest więcej niż jeden `<header>`, bo `RouteView` i bloki emitują nagłówki wewnątrz `<main>`. Landmark strony jest pierwszym dzieckiem `<body>`. Stopka jest jedna i stoi po slocie.

### Przeglądarka

Headless Chrome `/usr/bin/google-chrome`, Playwright 1.56.1, nowy kontekst na każdy przypadek. `web.sh shot` robi zrzut, zanim odroczony loader dorysuje baner. Zrzuty banera są z Playwrighta, po pojawieniu się przycisku **Akceptuję wszystkie**.

Przed kliknięciem, na trzech ścieżkach, stan to `necessary: true`, `measurement: false`, `marketing: false`, `source: default`, polityka `zawlodzki_global_opt_in_v2`, schemat `1`. Baner ma przyciski **Dostosuj**, **Odrzucam opcjonalne** i **Akceptuję wszystkie**. Dialog jest jeden.

`GET /api/c15t/init` z originem `http://127.0.0.1:8790` i `http://localhost:8790` zwraca 403 i nie ma `Access-Control-Allow-Origin`. Ten sam odczyt dla `https://www.zawlodzki.pl` i `https://zawlodzki-web.zawlodzki.workers.dev` zwraca 200 z pasującym ACAO. Konsola lokalnego workera ma błąd CORS na `/api/c15t/init` i ostrzeżenie loadera o trybie offline. Baner rysuje się mimo tego. Zapisu do API nie ma. Wybór zostaje w `localStorage` pod kluczem `zawlodzki-consent`. Po próbie zapisu dochodzi klucz `c15t-pending-consent-submissions`, bo `POST /api/c15t/subjects` dostaje ten sam CORS.

**Odrzucam opcjonalne** zostawia `measurement: false` i `marketing: false`, zamyka baner i trzyma ten stan po przeładowaniu oraz na `/kontakt`.

**Akceptuję wszystkie** ustawia oba sygnały na `true`. Stan zostaje po przeładowaniu. Baner nie wraca.

**Dostosuj** otwiera się też klawiszem Enter na skupionym przycisku. Przełączniki to Strictly Necessary (włączony i zablokowany), Analytics oraz Marketing. **Save Settings** po włączeniu samego Analytics daje `measurement: true` i `marketing: false`. Po przeładowaniu baner nie wraca, a ten podział zostaje. Etykiety dialogu są po angielsku. Etykiety banera są po polsku. Oba zestawy pochodzą z loadera c15t.

Przed kliknięciem loader sam pobiera `gtm.js` i skrypty `gtag.js`. Jest też żądanie zbierające Google z `gcs=G100` i `npa=1`. Po pełnej akceptacji pojawia się żądanie z `gcs=G111` i `npa=0`. To jest zachowanie z checklisty T06. GTM startuje jako skrypt necessary przed wyborem. GA4 i reklamy mogą wysłać ping bez ciasteczek przy odmowie. Drugiego snippetu GTM w HTML nie ma.

`[data-c15t-open]` ma liczbę 0. Ten atrybut dodaje T27.
