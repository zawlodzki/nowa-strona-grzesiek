# T61. Protect main: no force-push, no deletion, CI required for PRs

## Goal

On 2026-11-12 `main` had no branch protection and no rulesets (`gh api repos/zawlodzki/nowa-strona-grzesiek/branches/main/protection` returned 404, `/rulesets` returned `[]`). The repo is public. `AGENTS.md` says agents never merge, force-push or rewrite `main`, but nothing enforces it.

Changing repository settings is an external change. Prepare the proposal, then apply it only after the user's explicit yes.

## Constraint: claim commits

Agents push claim commits and board changes directly to `main` (AGENTS.md, "Working on a task"). A rule that requires a pull request for every change would break that protocol. The proposal must keep direct claim pushes working, or change the protocol in `AGENTS.md` in the same PR.

## Steps

1. Check what GitHub offers for this account and repo type (rulesets, bypass lists, required status checks). Do not assume; read the current docs and record the source.
2. Write the proposal in `migration/lanes/platform/out/t61-branch-rules/`. The minimum is: block force-pushes and deletion of `main`. Then evaluate a required `CI` status check for pull requests, and say how claim commits pass (a bypass for the owner, or a protocol change).
3. After the user's yes, apply the rules with `gh api` and save the request and the resulting ruleset JSON as evidence.
4. Prove it: a force-push to `main` from a scratch clone is rejected; a claim-style commit still lands; a PR with a failing CI cannot be merged (if that rule was approved).
5. Update the `AGENTS.md` wording so it matches what is enforced.

## Done when

- [ ] The proposal names each rule, why, and how claim commits keep working.
- [ ] After approval, the rules are active and the three probes above are recorded.
- [ ] `AGENTS.md` matches the enforced rules.
- [ ] `tasks.py check` passes; PR opened with status `review`.
