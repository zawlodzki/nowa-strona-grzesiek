# T108. Run the schema-to-contract check in CI

## Goal

`node apps/studio/scripts/verify-schema.mjs --schema-only` compares the Studio schema with `migration/contracts/blocks.json` (page blocks, their fields, Portable Text members and styles). It is not in CI, so T54 merged a new block (`sectionRef`) that broke it and nobody noticed until T94. Run it on every PR so schema and contract cannot drift again.

## Requirements

1. Make CI run `sanity schema extract --path schema.json --force` and then `node scripts/verify-schema.mjs --schema-only` in `apps/studio`. `schema.json` is gitignored, so the extract step is required. Prefer the smallest wiring: a script in `apps/studio/package.json` picked up by the existing `pnpm check` or `pnpm test` step. Add a separate step in `ci.yml` only if that does not work.
2. The step must not need a Sanity login, token or network access to the Content Lake. `--schema-only` already skips document validation. Confirm extract also runs without credentials.
3. Do not change the schema, the contracts or `verify-schema.mjs`. If the check fails on `main`, stop and record it under Handoff as a contract or schema request.

## Done when

- [ ] On a fresh checkout, the command CI runs passes and prints `PASS contract blocks, fields, Portable Text members and styles`.
- [ ] Negative check: with a block type temporarily removed from a local copy of `blocks.json` (not committed), the same command exits non-zero. Paste both outputs under Handoff.
- [ ] The PR's CI `build` check runs the step and is green.
- [ ] `tasks.py check` passes. PR opened with status `review`. Do not merge.
