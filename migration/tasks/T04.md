# T04. DESIGN.md and design tokens proposal

## Goal

Describe the incumbent visual world and propose tokens and per-block refine changes.

## Inputs

- PRODUCT.md
- migration/lanes/design/out/audit.md
- migration/00-inventory/webflow/design-tokens.json
- migration/00-inventory/webflow/scripts.json
- migration/contracts/blocks.json

## Steps

1. `impeccable document`: DESIGN.md with colors actually used on live pages (not the full SystemFlow palette), Satoshi and Erode type scale, spacing, radii, components. Note the root font-size 20px/16px quirk.
2. `impeccable extract`: `tokens.json` with color, fluid type scale (clamp), space, radius, shadow, breakpoints.
3. `blocks-refine.md`: for each block in blocks.json, its current visual pattern and the refine changes. Flag any block the design does not fit.

## Done when

- [x] Every color in tokens.json appears on at least one live page (cite the page).
- [x] blocks-refine.md covers all 12 blocks.

## Handoff

**What changed.**
- `DESIGN.md` (repo root) is the impeccable `document` output. It has DESIGN.md-spec frontmatter (23 colours, 9 type roles, radii, spacing, 20 component variants) and the 8 canonical sections. It documents the colours live pages actually use, the Satoshi and Erode scale, layout, elevation, shapes, components and do's and don'ts. The root font-size quirk (`html{font-size:20px}`, 16px at <=991) is under Typography.
- `migration/lanes/design/out/tokens.json` is the impeccable `extract` output, in DTCG format (`$type`/`$value`). It holds:
  - 24 primitive colours, each with `$extensions.zawlodzki.seenOn` (page path), `selector`, `use` and, where relevant, `contrast`;
  - semantic text, surface and border aliases;
  - font families and weights, 9 fluid typography roles;
  - space, layout, radius, border-width, shadow and focus-ring tokens;
  - breakpoints (min-width 480/768/992/1280) and motion.
- `migration/lanes/design/out/blocks-refine.md` covers all 12 blocks. For each it gives where the block appears, its current pattern, the refine changes, and a fit verdict naming every misfit. It ends with the live sections no block covers.

**How the type scale works.** Each role is `clamp()` with linear interpolation from its rendered px at 390 (old 16px root) to its rendered px at 1440 (old 20px root). The root stays at 100%. T08's "renders identically at 1440px and 390px" check therefore compares against the px pairs in `typography.*.$extensions.zawlodzki.px390/px1440`.

**Refine decisions (not incumbent values), each tied to the T03 audit.**
- Taglines and placeholders: Fog #838d95 moves to Slate #636b75, and tagline weight 400 moves to 500 with +0.04em tracking (audit 10).
- Tier tags: Atlas Blue on Cyan Tint, 6.55:1. The audit proposed #06687f, but that colour is on no live page and would break the "Every color appears on a live page" check (audit 11).
- On-dark links: primary-20 #b0b6eb, seen on /sales-atlas-system (audit 12).
- Error text: #d0463b (4.54:1, from the /automatyzacje-dla-pipedrive scenes) instead of SystemFlow #f5222d (4.08:1).
- Secondary button pressed: Atlas Blue Tint instead of #08a6cb, which put blue text at 2.46:1.
- Section padding: 48px at 390 (live is 64px at all widths). The blog hero radius 16px moves to 20px, and all boxed surfaces use 20px.
- No gradient text, no hover gradient on buttons, and no cyan third pricing tone.

**Deviations.**
- No `.impeccable/design.json` sidecar. impeccable `document` writes one, but it is not in this task's `owns`. A follow-up can add it, or T08 can own it.
- impeccable `document` step 3 asks the user for qualitative language (north star, colour names). I chose them from PRODUCT.md and the audit: "The Working Pipeline", Atlas Blue, Night Navy, Signal Cyan. They are names only and change no value, so they are cheap to rename.
- The compiled Webflow CSS (`zawlodzki.webflow.shared.4d3d36fc0.min.css`) is not in the inventory. I fetched the public file into session scratch to resolve which rules match live HTML. It is not committed. Suggest the inventory owner adds it to `migration/00-inventory/webflow/`.

**Evidence.**
- Colours: a script checked each of the 24 colours. For each one, the cited page file exists in `live-site/html/`, and the hex is either in that page's HTML or in a compiled-CSS rule whose class is on that page. Result: 24/24 OK, exit 0. Shadow alphas #00000014, #5d637026 and #5d637033 are present in the compiled CSS.
- Typography: a script compared every fontSize in the DESIGN.md frontmatter with tokens.json. All 9 match.
- Contrast pairs were computed with the WCAG formula. The values are quoted in tokens.json `contrast`.
- Blocks: blocks-refine.md has sections 1 to 12 matching every `type` in blocks.json.
