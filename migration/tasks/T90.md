# T90. Hero portraits use the clean cut-out, tool pages get a logo badge

## Goal

Every hero shows the same clean portrait cut-out with nothing baked in behind it, as `/szkolenie-i-wdrozenie-salesforce` does today. Pages about one tool add that tool's logo as a badge over the portrait, again like the Salesforce page.

## Context

Owner request, 2026-11-13. The Hero block already supports this: `image`, `badgeImage` and `badgeSize` (`standard` | `wide`), rendered by `Hero.astro` as `.image-badge` over the portrait. So this is mostly a content change in Sanity plus a visual check of each badge.

## Requirements

- Reuse the existing clean cut-out asset already in the dataset (the one on the Salesforce page). Do not upload a duplicate.
- Badge logos: the official colour logo of each tool, as a transparent PNG/SVG/AVIF from the vendor's own brand or press page. Follow each vendor's logo usage rules (clear space, no recolouring). The Pipedrive logo must be consistent with the authorised-partner use already on the site. Record the source URL of every logo in Handoff. For n8n use the current logo from n8n's brand page, not the older mark shown in the tools logo strip. If a suitable logo document already exists in Sanity, reuse its asset.
- Each badge sits over the lower-left torso area like the Salesforce one, does not cover the face, and stays inside the hero at 390, 768 and 1440 px. Choose `badgeSize` per logo shape (wordmarks are usually `wide`). If a logo needs a size or offset the two presets cannot give, adjust `Hero.astro` in a general way (no per-tool CSS).
- Alt text: portrait "Grzegorz Zawłodzki", badge "<Tool> logo". Fix the leftover alts ("Grafika: Frame 28 compressed" on home, "Grafika: Frame 51", "grzegorz zawłodzki logo make.com").
- LCP: the portrait stays `eager`. Badge images have explicit width and height. No layout shift.
- `og:image` / JSON-LD `primaryImageOfPage` read the hero image (`seo.ts`). Confirm the change is acceptable there, or keep a dedicated SEO image, and say which.
- **Human gate.** Uploading assets, patching the `hero` sections and publishing in the production dataset need the owner's explicit yes at the moment of the action. Prepare everything as drafts (or a content release) first, show the owner screenshots, then publish on approval. Webflow stays read-only.
- Do not touch `apps/web/src/components/diagrams/**`.
