# T54. Reusable sections category (reusableSection + sectionRef)

## Goal

The same blocks are copied onto many pages (the investigation counted 15 identical contact forms and 6 identical newsletters). Grzesiek wants a Studio category "Sekcje" so a section can be edited once and attached to pages.

For now: new document type + reference only. Do not merge or replace the existing inlined copies. Deduplicating production content is a later task and needs his explicit yes, because it writes the production dataset.

Depends on T47 (documents.ts / typegen), T50 (`sanity.config.ts` / `structure.ts`), T52 (`documents.ts`, `Sections.astro`, `site.ts`) and T53 (form/newsletter fields should exist before a reusable form/newsletter section is useful; also `blocks.ts` and typegen).

## Requirements

1. Add a `reusableSection` document type (Polish title "Sekcja") that holds one block (at least `newsletterSignup` and `contactForm`, and other block types if that is a small extra). Give Studio a "Sekcje" list for these documents. Do not use a new document type for legal pages; that is T50.
2. Add a `sectionRef` block that pages can insert in `page.sections`, pointing at a `reusableSection`. Resolve it in `Sections.astro` / `site.ts` so the referenced block renders like an inlined one, including form and newsletter fields from T53.
3. Existing inlined sections stay as they are. No migration script, no production write, no automatic conversion of the 15 forms or 6 newsletters.
4. Run typegen. Prove in local Studio that a Sekcje document can be created and referenced, and on a local page that a `sectionRef` renders the referenced block. Evidence in `migration/lanes/cms/out/t54-reusable-sections/`. Stop dev servers at the end. Do not deploy Studio.

## Done when

- [x] Studio has a "Sekcje" category of `reusableSection` documents.
- [x] A page can include `sectionRef` and the site renders the referenced section.
- [x] No existing page section was migrated or rewritten in Sanity.
- [x] Typegen is updated. `tasks.py check` passes; PR opened with status `review`. Do not merge. No production Sanity write.
