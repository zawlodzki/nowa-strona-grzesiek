# T48. Blog post layout: collapsible TOC, mobile CTA, column alignment, share icons, related-posts motion

## Goal

Grzesiek's feedback on https://zawlodzki-web.zawlodzki.workers.dev/blog/automatyzacja-sprzedazy (and the in-page hash `#post-od-czego-zaczac-automatyzacje-sprzedazy`). The fixes belong in the shared post template and must apply to every blog post, not only this one. Do not add per-post hacks.

T47 was already claimed for a different board item (pre-cutover SEO). This work is T48.

Standing prefs: no cyan anywhere; Atlas Blue `#3a48cc` for accents. Do not change CTA copy.

## Current code (inspect 2026-11-12)

- Layout lives in `PostView.astro`. The header uses `.content-grid` (container max `--layout-container-max` / 78rem, content track = that minus gutters) and `.post-head .inner` is further limited to `--measure-prose` (68ch), so the title and hero sit in the site content column. `.post-layout` is a separate centered box: `inline-size: min(100% - 2 * var(--space-m), 88rem)`. 88rem is wider than the 78rem content-grid container, so the TOC column starts further left than the title and hero image.
- Three columns (TOC / content / right CTA) exist only at `min-width: 75rem`. Below that, TOC, content and the right column all stack. At the 3-column threshold both side columns stay and the content column gets squeezed.
- The right-column card (`.sidebar-cta`) and the `<CtaBand>` after the author block use the same heading (`post.cta?.label` or "Porozmawiajmy o Twojej firmie") and the same button ("Umów konsultację"). On mobile they appear one under the other. Related posts (`Sprawdź również`) sit in the same right-column aside, always visible today. There is no separate related-posts component; `RelatedPosts.astro` is reserved in `owns` if you extract one.
- `PostToc.astro` is always expanded. There is no disclosure control.
- `SharePost.astro` keeps the T39 equal-tile 2-column grid of six actions. The glyphs are crude stroke-path approximations; the X mark is not the official x.com logo, and LinkedIn and WhatsApp are similarly off. Check Facebook, Email and Copy link too.

## Requirements

1. **Mobile TOC.** The table of contents must be collapsible on mobile. Use an accessible pattern (`<details>` or a button with `aria-expanded`). Collapsed by default on mobile is fine. When the TOC sits in the desktop side column it must stay expanded and usable (sticky active-section behaviour in `PostToc.astro` remains).
2. **Mobile CTA duplicate.** Hide one of the two identical CTAs (sidebar `.sidebar-cta` and the bottom `CtaBand`) on mobile so only one shows. Keep related posts. Do this in `PostView.astro`; do not edit `CtaBand.astro` (it is shared with other pages). CTA copy stays unchanged.
3. **Full-width alignment.** The 3-column layout (TOC / content / right CTA column) must align coherently with the header / title / hero grid. The TOC must not start further left than the title and hero. Prefer a scoped fix in `PostView.astro`. Do not change global `layout.css` or tokens unless there is no other way; if that becomes necessary, add the file to `owns` in the PR and say why.
4. **Responsive column order.** When the viewport narrows, the right column should disappear first so the content keeps its width and the TOC can stay at the side. Only later should the TOC leave the side (and become the collapsible mobile TOC). Do not keep both side columns once they start squeezing the article.
5. **Share icons.** Replace the X glyph with the real x.com logo, and use proper LinkedIn and WhatsApp brand marks. Review the other tiles too. Keep the equal-tile grid from T39. No cyan; Atlas Blue `#3a48cc` is allowed for accents.
6. **Related posts appear mid-article.** The related posts list (`Sprawdź również` / powiązane wpisy) in the right column must appear only after the reader scrolls to about half of the article content, with an enter animation, and disappear with an exit animation if they scroll back up above that point. This applies to the related list, not the sidebar CTA card. Follow Emil Kowalski's published animation skills from https://github.com/emilkowalski/skills (start with `skills/animate/SKILL.md` and `skills/emil-design-eng/SKILL.md`; use `review-animations` on the result). Read them from a temp checkout; do not install them into this repo's agent skill dir unless the path is already in `owns` (it is not). Guidance to follow: ease-out custom curves, short durations ~200–300ms, `transform` and `opacity` only, respect `prefers-reduced-motion` (instant show/hide, no motion), no layout shift. If you extract the list from `PostView.astro`, put it in the reserved `RelatedPosts.astro`.
