# T124. Studio plugins: visible icons for Otwórz podgląd and Do uzupełnienia

## Goal

T122 and T123 shipped and deployed, but editors cannot see either control. Sanity 6.20 draws document header buttons as icons only. Neither plugin passes an `icon`, so both buttons render 0 px wide. Found on 2026-11-20 in the hosted Studio and in local `sanity dev`: the DOM holds buttons labelled "Do uzupełnienia" and "Otwórz podgląd" with zero width and no SVG.

## Requirements

1. Give both header controls an icon from `@sanity/icons`. The icon must be a module-level constant. An inline component crashes the Studio with React #301, because the field action resolver compares items by reference.
2. Render the **Do uzupełnienia** panel with `@sanity/ui` components instead of raw HTML, so it matches the rest of the Studio.
3. Extend the tests so a missing or unstable icon fails them.
4. Studio only. Do not deploy Studio and do not write to the production dataset.

## Done when

- [x] In local `sanity dev`, a post shows both icons in the document header. Clicking **Otwórz podgląd** opens Presentation on the post URL. Clicking **Do uzupełnienia** opens the styled panel. Screenshots in `migration/lanes/cms/out/T124/`.
- [x] `pnpm --filter studio test`, `pnpm --filter studio check`, `pnpm --filter studio build` and `tasks.py check` pass.

## Handoff

- **Root cause.** Sanity 6.20 renders document header items as icon-only buttons. T122's inspector menu item and T123's field action had no `icon`, so both buttons were 0 px wide. Confirmed in the DOM of the hosted Studio and local `sanity dev` on 2026-11-20 (`00-hosted-before.jpg`).
- **Fix.** `open-in-presentation.tsx` uses `EyeOpenIcon`. `editorial-markers.tsx` uses `WarningOutlineIcon`. The panel now uses `DocumentInspectorHeader` from `sanity/structure` and `@sanity/ui` (`Flex`, `Box`, `Stack`, `Card`, `Text`) instead of raw HTML.
- **Dependencies.** Added `@sanity/icons` 5.2.3 and `@sanity/ui` 4.4.9 as direct dependencies, pinned to the versions `sanity` 6.20.0 already resolves, so the panel shares the Studio's theme context. The lockfile also moved `@sanity/language-filter` from `@sanity/ui` 4.4.10 to 4.4.9 by dedupe.
- **Deviation.** `@sanity/icons` 5 exports single icons only from subpaths (`@sanity/icons/EyeOpen`). Its root `index.d.ts` still declares the named icons, so `tsc` passes on a root import that fails at runtime.
- **Tests.** `open-in-presentation.test.mjs` asserts an icon and adds a negative control: an inline icon component exceeds the render budget (React #301). New `editorial-markers-inspector.test.mjs` checks the menu item icon, the caution tone with a `[[TODO: …]]`, the type filter, and the same inline-icon negative control. `pnpm --filter studio test`: 37 pass.
- **Evidence.** Local `sanity dev` against production, read-only. `01-header-icons.jpg` shows both icons. `02-markers-panel.jpg` shows the styled panel with 0 markers on post `post-6a5e8ad6238b858c957e3b51` (its text says "listami TODO", not a marker). `03-presentation-opened.jpg` shows Presentation at `/blog/aplikacje-ktore-sprawdzilem-w-4-biznesach`. `check.log` and `build.log` pass. `tasks.py check` passes.
- **Not verified.** The panel's list state and click-to-open with a real marker: no document has one, and I did not write a draft to production. The preview iframe stays on "Loading." in local `sanity dev`; not investigated, outside this task.
