# T93. Shorten CTA labels that wrap buttons to two lines

## Goal

No CTA button wraps its label to two lines, including when the button is full width on a phone. Fix it in the content: find every label that wraps and shorten it, keeping its meaning and the first-person voice.

## Context

Owner request, 2026-11-13. Measured on staging the same day: 27 pages (every non-blog page in `sitemap-pl.xml` plus 3 posts), viewports 390, 768, 1024 and 1440 px. 96 buttons per viewport, 42 distinct labels, 59 wrapped instances. Lines were counted from the label's client rects. Selectors: `a.action:not(.text)`, form submit buttons and the header CTA.

What the numbers say:

- **Full width at 390 px.** The button is about 310 px wide in a CTA band and about 294 px in a pricing card. The longest labels that still fit on one line there are 31–32 characters ("Porozmawiajmy o automatyzacjach"). Five CTA-band labels of 36–43 characters wrap.
- **CTA band at 1024 and 1440 px.** The four labels of 41–43 characters wrap even in a 466 px button.
- **Pricing cards at 1024 px.** The cards are about 250 px wide, so even a 22-character label wraps. That part is layout, not copy: three columns are too narrow at 1024 px. T83 owns the pricing card layout. Report it there, and do not shorten labels below what reads naturally just to fit 250 px.

Related tasks: T86 changes the button padding and adds the chevron/arrow, which changes the available width. T83 changes pricing cards. If either has merged when you start, measure on that main. Otherwise measure on current staging and note it.

## Requirements

- Re-run the measurement on current main (`wrangler dev`) or staging at 390, 768, 1024 and 1440 px across all pages in the sitemap, plus the blog index and at least 3 posts. Include CTA bands, pricing buttons, hero CTAs, the header CTA, sidebar CTAs and form submit buttons. Save the script and its output under `migration/lanes/web/out/t93-cta-labels/`.
- Set a label budget per context from the measurement (for example: CTA band and hero ≤ the length that fits one line at 390 px full width, pricing ≤ the length that fits the pricing button at 768 px). Write the budget in Handoff so editors can follow it.
- Propose a shorter label for every label over budget. Keep the meaning, the verb-first first-person voice of the site, and the specific object where it matters ("audyt Pipedrive", not just "audyt"). No new claims. Avoid making several CTAs on one page identical. Starting points, for the owner to accept or change:
  - "Zapytaj, czy kurs pasuje do Twojego procesu" → "Sprawdź, czy kurs pasuje"
  - "Umów konsultację o swoim systemie sprzedaży" → "Umów konsultację o systemie"
  - "Porozmawiajmy o audycie AI w Waszej firmie" → "Porozmawiajmy o audycie AI"
  - "Porozmawiajmy o pierwszym procesie dla AI" → "Wybierzmy pierwszy proces dla AI"
  - "Zapytaj o udział zespołu w programie" → "Zapytaj o program dla zespołu"
  - "Umów rozmowę o audycie Pipedrive / sprzedaży / Asany" → "Umów audyt Pipedrive / sprzedaży / Asany"
  - "Porozmawiajmy o zakresie i cenie" → "Zapytaj o wycenę"
  - "Umów rozmowę o diagnozie CRM" → "Umów diagnozę CRM"
- Show the owner the before/after list (page, block, old label, new label, length) and get explicit approval before any write.
- **Human gate.** Changing labels means writing to the production Sanity dataset. Prepare the changes as drafts or a content release, get the owner's yes at the moment of publishing, then publish. Do not change component code in this task. If a label cannot fit without losing its meaning, leave it and record it as a layout issue for T86 (CTA band) or T83 (pricing).
- If a label comes from code (for example the default consultation link in `apps/web/src/components/ui/block-types.ts`), do not edit it here. Write it under Handoff as a follow-up.
