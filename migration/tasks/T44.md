# T44. Heading anchors on product/service pages

## Goal

Grzesiek wants section headings on product/service pages (e.g. /szkolenie-i-wdrozenie-asana, /audyt-sprzedazy, /szkolenie-i-wdrozenie-pipedrive, /wdrozenie-ai-w-sprzedazy-b2b, /kurs-ai-w-sprzedazy, /sales-atlas-system) to have stable anchors so Google can show "jump to" links under the result. Today almost no h2/h3 has an `id` (staging check 2026-11-11: asana 4/32, audyt-sprzedazy 4/33), and there are no `#` links.

1. Add a small shared helper `apps/web/src/lib/headings.ts` producing stable, readable Polish-safe slugs (strip diacritics: ą->a, ł->l, etc.; lowercase; hyphens; dedupe per page with -2, -3) and unit tests.
2. Every section h2 and in-content h3 rendered by the shared blocks gets a unique `id` from its text (keep existing ids such as `kontakt-heading` working; if an aria-labelledby relies on an id, keep or update consistently). Ids must be identical between builds (no random keys).
3. Make headings linkable: `scroll-margin-top` so the sticky header doesn't cover them; optional subtle hover "#" link only if it fits DESIGN.md (otherwise skip).
4. Do not touch the blog post template (T39 owns PostView / components/post) nor Tabs.astro (T43).

## Done when

- [x] Every service-page main-content h2/h3 rendered in the approved scope has a unique stable id; full-document before/after counts and excluded footer/blog headings are documented in out/t44-anchors/.
- [x] Opening `/<page>#<id>` lands on the heading with the header not covering it (verify-web screenshots on port 8790/8791, wrangler dev --local).
