# T72. IndexNow: key file and production-only URL submission

## Goal

Tell search engines about changed URLs through [IndexNow](https://www.indexnow.org/documentation) (`POST https://api.indexnow.org/indexnow`) after content goes live, instead of waiting for a recrawl. The key file is public (`GET /<key>.txt` must return the key). The key is not a secret, but it must be generated once and stored as config (a tracked public file or a non-secret Wrangler/env var), not invented at request time.

This task builds and tests the mechanism. It must never submit from staging, from `wrangler dev`, or from a laptop.

## Human gate

The first real submission from production, and turning the production hook on, need the user's explicit yes. Ship the code with submission disabled by default (a documented env flag such as `INDEXNOW_ENABLED`, unset everywhere). Do not change the Workers Builds dashboard command, do not call `api.indexnow.org` against real URLs, and do not enable anything on `www.zawlodzki.pl`. After the PR is merged, record under Handoff the exact one-line follow-up (the command to append, the flag to set, and that it waits for "tak"). Bing Webmaster and GSC changes are out of scope.

## Steps

1. Generate a key (URL-safe, stable). Store it as config in this repo or as a named public env var. Serve `GET /<key>.txt` with `200`, `text/plain; charset=utf-8`, and the key as the body. Do not add this file to the sitemap. Prefer an Astro route under `apps/web/src/pages/` or a static public file so this task does not need `apps/web/src/worker/index.ts` (T71 owns that file while it is active). If the `owns` paths above need to change to match the design, update them in the PR and say why.
2. Write `migration/tools/indexnow.mjs` (Node, no new dependencies if possible) that submits the changed production URLs to `https://api.indexnow.org/indexnow` with the key and the host `www.zawlodzki.pl`. Choose a sound change set and document it: for example URLs that appeared or changed in the sitemap (and the matching `.md` URLs from T59, if you include them) since the last successful submit, or the URLs touched by the deploy. Refuse to run unless every one of these is true: `INDEXNOW_ENABLED` is set, the deployment target is production, and the host is `www.zawlodzki.pl`. A dry-run flag prints the payload and exits zero without posting.
3. Unit-test: the key route body; a dry-run payload against a fixture; a mock IndexNow endpoint that records the POST; refusal on staging, on localhost, and when the flag is unset (no HTTP request leaves).
4. Hook path. Today a Sanity publish hits the Workers Builds deploy hook (`apps/web/src/preview/README.md`, "Published-content rebuild hook"): `pnpm --filter web build` then `pnpm --filter web exec wrangler deploy`. There is no deploy-hook handler in the repo. Add a script the production deploy can run *after* a successful production deploy (not during `wrangler dev`, not in the current staging deploy). Do not edit the Cloudflare dashboard. Point at that script from the evidence folder. If T66 later splits environments, IndexNow must stay production-only; note that under Handoff.
5. Do not edit `apps/web/wrangler.jsonc`, `apps/web/wrangler.preview.jsonc`, or `apps/web/.dev.vars.example` while T65 is active. Do not edit `apps/web/src/preview/README.md` while T66 is active; put operator steps in `migration/lanes/seo/out/t72-indexnow/` instead.
