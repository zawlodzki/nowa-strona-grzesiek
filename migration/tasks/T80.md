# T80. Lighthouse CI with score thresholds and a page weight budget

## Goal

Catch performance, accessibility, SEO and page weight regressions in CI before they reach production. A new large pre-consent script must fail the check; reducing existing GTM loading before consent is a separate future task.

## Requirements

- Run Lighthouse CI as a new job in the existing `.github/workflows/ci.yml`. Do not add a second workflow.
- Audit the static build served by `wrangler dev --local`, not `astro dev`. Cover at least `/`, `/blog`, one blog post, one service page, `/kontakt` and `/newsletter`.
- Use the mobile preset and at least 3 runs per URL. Assert on the median.
- Start from the T76 baseline in `migration/lanes/platform/out/t76-web-perf/results.md`. Fail when performance drops below 85 or accessibility, best practices or SEO (excluding only `is-crawlable`) drop below 95. Fail on CLS above 0.1 and LCP above 2.5 s.
- Add a resource budget for total weight, script weight and third-party weight on a page load without consent. Set per-page limits to the measured current median plus a 5–10% margin. Record why each number was chosen.
- Keep the job deterministic. Use the Turnstile test key, and do not depend on live third-party responses beyond what the page loads by itself.
- Upload the Lighthouse reports as a CI artifact.
- Owner-approved revision (2026-11-13): disable only `is-crawlable` and compute SEO from the remaining audits. Local/staging noindex is intentional; existing tests cover production robots headers. Existing GTM before consent is baseline, not remediation scope.

## Done when

- [ ] The CI job passes on the PR and uploads reports for every audited URL.
- [ ] A throwaway commit that adds a large script before consent makes the job fail. Link the failing run in Handoff, then revert the commit.
- [ ] Thresholds, budgets and measured medians are recorded in `migration/lanes/platform/out/t80-lighthouse-ci/`.
