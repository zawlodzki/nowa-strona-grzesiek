# T106. Remove the dead Webflow diagram port tooling

## Goal

After T92 and T96–T105 every one of the 52 diagram scenes is hand-built in the calm scene style and carries the header marker `port-diagrams.mjs no longer writes this file`. No scene imports `diagram.css` or uses the `.dg` shell with `--dg-w`/`--dg-h`. The tooling that ported the Webflow embeds, measured them and checked parity is now dead weight. Remove it.

## Context

- The branch starts from the T105 branch (PR #119), which sits on T96–T104 (PRs #107–#118). Merge those first.
- Candidates: `diagrams/diagram.css`, `port/sizes.json`, `port/measure-diagrams.mjs`, `port/parity-diagrams.mjs`, `port/layout-diagrams.mjs`, `port/cdp.mjs`, `port/embeds.mjs` and the scene writing in `port/port-diagrams.mjs`.
- `registry.ts` and `Diagram.astro` are still used (`Diagram.astro` by the pages, `registry.ts` by `/_ds/diagrams`). Either keep a generator for them or turn them into static files.
- `port/port-diagrams.mjs` is listed in the `owns` of T96, which is still in review, so the board check would reject owning it here. Its deletion is recorded as a deviation in the Handoff.

## Requirements

1. Grep the repo (including `migration/tools`, CI, `AGENTS.md`, other tasks and lane outputs) and keep anything still referenced.
2. Delete what is dead. Keep `registry.ts` and `Diagram.astro` working.
3. No visible change on `/_ds/diagrams` or the pages that use diagrams.

## Done when

- [x] The dead files are deleted and nothing still references them.
- [x] `pnpm --dir apps/web check` and the build pass.
- [x] `/_ds/diagrams` renders all 52 scenes, unchanged.
- [x] `tasks.py check` passes. PR opened with status `review`. Do not merge.

## Handoff

**What changed** (`apps/web/src/components/diagrams/`):

- Deleted `diagram.css` (the `.dg` / `--dg-w` / `--dg-h` sizing shell; no scene imports it after T105).
- Deleted `port/port-diagrams.mjs`, `port/embeds.mjs` (only the port and the parity check read it), `port/sizes.json`, `port/measure-diagrams.mjs`, `port/parity-diagrams.mjs` and `port/layout-diagrams.mjs`.
- Dropped the generator instead of slimming it: `registry.ts` and `Diagram.astro` are now static, hand-maintained files. Their headers say so. `Diagram.astro` keeps the `satisfies Record<DiagramKey, unknown>` guard, so a key added to one file but not the other fails `astro check`. Rebuilding them from the inventory would only regenerate a list of 52 keys that no longer comes from Webflow, so a generator is not worth keeping.
- Both files are formatted with the repo's Prettier config (they were generated unformatted before). This is cosmetic only.

**Kept:** `port/cdp.mjs`. The archived lane scripts `migration/lanes/design/out/t41-cta-audit/{collect,shot-chrome}.mjs` and `t42-cta/{compare,shot}.mjs` import it by path, and those files belong to T41 and T42.

**Grep:** `.github/`, `migration/tools/`, `AGENTS.md`, `CLAUDE.md`, `DESIGN.md`, `README.md`, ESLint, Prettier and package configs have no reference to the deleted files. The remaining references are history: T11, T67, T76 and T92–T105 task files, the T67 lint lane output, and the scene header marker `port-diagrams.mjs no longer writes this file` in the 52 scene files, which T92–T105 own. The marker is now harmless but stale.
