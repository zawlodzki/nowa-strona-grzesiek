# T120. Prefetch likely next pages with Speculation Rules

## Goal

The site is a multi-page Astro site served from the edge, and it has no speculative loading: no `<script type="speculationrules">` and no Astro `prefetch`. The `improve-next-page-load-performance` guide in the `modern-web-guidance` skill recommends document rules for static, edge-cached pages. It is a progressive enhancement: browsers without support ignore it.

Found in the modern-web-guidance audit of 2026-11-15.

## Requirements

1. Add one inline `<script type="speculationrules">` to `Base.astro` with a same-origin **prefetch** document rule (`where`/`href_matches: "/*"`) at `eagerness: "moderate"` and a `tag` (for example `zawlodzki-prefetch`).
2. Use prefetch, not prerender. Prerender would run GTM, the c15t loader and Turnstile in a page the visitor may never see, which skews analytics and consent. Prerender may be proposed in Handoff as a follow-up only.
3. Exclude at least: Worker endpoints that accept form posts or change state, `*.md` and `*.txt` / `*.xml` machine routes, links with `rel~=nofollow`, links with `target=_blank`, the Sanity preview routes and any `download` links. Check the Worker routes in `apps/web/src/worker/` for anything else to exclude.
4. Keep the consent defaults script the first script in `<head>`. The speculation rules must not change its order or the CSP, if one exists.
5. Add `apps/web/e2e/speculation.spec.ts`: the rules script is present, parses as JSON and has the exclusions. In Chrome, use `verify-web` to prove that hovering an internal link issues a prefetch request (`Sec-Purpose: prefetch`) and that excluded links do not.
