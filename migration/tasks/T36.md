# T36. Tabs block: sticky panel and scroll-driven layers

## Goal

Grzesiek's feedback on https://zawlodzki-web.zawlodzki.workers.dev/sales-atlas-system (layer tabs section):
1. The panel with layer descriptions must be stuck to the top (top-aligned, sticky), not vertically centred; it must not move when switching layers.
2. While the page scrolls through the section, layers must switch automatically one after another (scroll-driven), while clicking a tab still works.

The change lives in the shared Tabs block, so it applies on every page that uses it.

## Done when

- [x] Panel is top-aligned and sticky on desktop; its top edge does not move when switching any layer (prove with screenshots of at least 2 layers at the same scroll offset).
- [x] Scrolling through the section advances the active layer in order and back on scroll up; clicking a tab still works and keeps scroll/state consistent.
- [x] Mobile 375 and mid widths stay usable (no broken sticky, no scroll trap); respects prefers-reduced-motion.
- [x] Keyboard and ARIA tab semantics still correct.
- [x] verify-web evidence: screenshots live vs new at 1440 / 768 / 375 plus a scroll sequence showing auto-switching.
- [ ] `tasks.py check` passes; CI green.

## Handoff

**What changed.** Only `apps/web/src/components/blocks/Tabs.astro`, so the change reaches every page that uses the Tabs block. `_ds/blocks-a.astro` needed no change; it already renders the Atlas tabs at `#t32-tabs`.

- Markup: `.menu` and `.panels` now sit in a `.stage` wrapper, followed by an empty `aria-hidden` `.runway`. `.tabs` carries `--layers: <item count>`.
- Top alignment always: `.stage` uses `align-items: start` (was `center` on `.tabs`). The panel top no longer depends on the menu height, so it stays put when switching layers in every mode.
- Scroll-driven mode (`[data-scroll]` on `.tabs`, set by JS): `.stage` becomes `position: sticky; inset-block-start: var(--tabs-top)` (5rem, just below the 72px header). `.runway` gets `block-size: calc(var(--layers) * var(--tabs-step))`, where `--tabs-step` is `clamp(12rem, 30svh, 20rem)` (270px at 900 high). The stage stays pinned for the length of the runway. The active layer is `floor((stickyTop - tabs.top) / step)`, clamped to 0..n-1, so it advances one layer per step going down and walks back going up. The scroll listener is passive and runs at most once per animation frame (rAF).
- The stage gets `min-block-size` set to its tallest layer (measured), so the track length is constant. Without it, each layer switch changed the track height and scroll anchoring shifted the page by 30-60px.
- Click, Space and the arrow/Home/End keys go through `select()`. It activates the tab and, when pinned, moves the page instantly (`behavior: 'instant'`, no smooth motion) to the middle of that layer's slice, so the next scroll event keeps that layer. Focus uses `preventScroll` while pinned. The tablist, tab, tabpanel and `aria-controls`/`aria-labelledby` wiring and the roving tabindex are unchanged.
- When it turns on (no scroll traps): only when `min-width: 992px` matches, `prefers-reduced-motion` is not `reduce`, and the tallest stage fits in `innerHeight - stickyTop` (+24px slack, under the panel's 40px bottom padding). This is re-checked on resize and on media-query changes. Otherwise the block stays click-only tabs with a top-aligned panel, exactly as before but no longer centred. The 768 and 375 stacked layouts are untouched (panel first, no sticky, no runway).

**Deviations.**
- To make the pinned stage fit a 1440x900 viewport, the menu is slightly tighter in scroll mode only: `gap` 16 to 8px and item `padding-block` 16 to 12px. Without that the menu is about 909px tall (9 items plus the open summary), which is taller than the space under the header on 900-1000px viewports, so the feature would almost never switch on.
- Reduced motion: scroll-driven switching (pinning plus auto-switching) is turned off entirely; the tabs work by click and keyboard.
- Short viewports, for example 1280x720: the stage does not fit, so scroll mode stays off by design. A pinned panel taller than the viewport would hide its bottom (CTA links).

**Follow-ups.** None required. If Grzesiek wants auto-switching on shorter laptop screens too, the panel content height is the limit, not the code.
