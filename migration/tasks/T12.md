# T12. SEO core: buildGraph, meta, hreflang

## Goal

One JSON-LD @graph per page and all head metadata from typed data.

## Inputs

- migration/contracts/entities.json
- migration/00-inventory/live-site/jsonld-summary.md
- migration/00-inventory/live-site/jsonld/

## Steps

1. `buildGraph(page)` per PLAN.md section 3 'JSON-LD docelowo'. Keep every existing @id. No SearchAction, no HowTo; FAQPage only when the faq block is visible.
2. Meta: title, description, canonical to www without trailing slash, one og:type, Twitter tags, hreflang only for real PL/EN pairs plus x-default to PL.
3. Snapshot tests for home, service, course, post, contact, about, compared against the live JSON-LD with intended differences listed.

## Done when

- [x] Tests pass.
- [x] Google Rich Results Test or schema.org validator shows no errors on the six samples (screenshots in Handoff).

## Handoff

**What changed.** All of it is in `apps/web/src/seo/`.

- `types.ts` is the input contract. `SeoPage` is a discriminated union on `kind` (`home`, `service`, `course`, `post`, `blogIndex`, `contact`, `about`, `generic`). Each kind carries only the data its JSON-LD needs. Routes (T18) map Sanity documents into it; the builders never touch Sanity.
- `graph.ts` exports `buildGraph(page)` and `serializeGraph(page)`. One `{"@context", "@graph"}` per page: the WebPage (`<url>#webpage`, subtype per kind), the kind's nodes (`#service`, `#course`, `#article` + `Blog` stub, `#blog`), `#breadcrumb` when the trail has two or more crumbs, `#faq` only when `page.faq` is passed, then Person, Organization and WebSite from `contracts/entities.json`. Every `@id` follows `entities.json` `idPatterns`; the PL home keeps `https://www.zawlodzki.pl/#…`. Cross-page references (home OfferCatalog, `/o-mnie` makesOffer, post → blog) are typed stubs. No SearchAction, no HowTo. `serializeGraph` escapes `<` so content cannot close the script tag.
- `meta.ts` exports `buildMeta(page)`: title, description, canonical (www, no trailing slash, `canonicalOverride` wins), `robots: noindex` when asked, exactly one `og:type` (`article` for posts), og:url/site_name/locale/image, `article:*` times, Twitter card tags, and hreflang `pl` + `en` + `x-default`→PL only when `page.translation` is set.
- `Seo.astro` renders both into `<head>`: `<Seo page={seoPage} />`.
- `fixtures/derive.mjs` rebuilds the six sample inputs (`home`, `service` = szkolenie-i-wdrozenie-pipedrive, `course` = kurs-ai-w-sprzedazy, `post` = blog/ai-w-sprzedazy, `contact`, `about`) from the live snapshot. Run `node apps/web/src/seo/fixtures/derive.mjs` (needs the inventory).
- `graph.test.mjs`, `meta.test.mjs`, `parity.mjs`: run `node --test apps/web/src/seo/`. Snapshot per sample in `__snapshots__/`, graph invariants (one graph, entities intact, every bare `@id` reference resolves in the graph, no SearchAction/HowTo, FAQPage iff visible FAQ, `</script>` escaping, EN ids), meta rules, and a parity diff against the live JSON-LD in which every difference must match a listed reason. `UPDATE_SNAPSHOTS=1` rewrites the snapshots and `PARITY.md`.
- `PARITY.md` is the generated list of intended differences from the live site, one row per change.

**Intended differences from live** (full table in `apps/web/src/seo/PARITY.md`): SearchAction dropped; WebSite and BlogPosting publisher is the Person and home `about` is the Person (decision 3); WebSite `inLanguage` is `["pl-PL","en"]` as in `entities.json`; Person `email` without `mailto:`; WebPage `description` is `seo.description` (Webflow had a second hand-written copy on the service and contact pages); service page gets `mainEntity` and the Service gets `url`; ProfilePage gets `about` and `description`; posts get `<url>#webpage`, `<url>#article` (was the bare URL), `mainEntityOfPage` by `@id`, `image` as ImageObject, a typed `/blog#blog` stub, and `<url>#breadcrumb` (was a blank node); Course `termsOfService` dropped because it is not a Course property (validator warned on it).

**Follow-ups and contract requests.**
- Contract request (C, T07 schema): the `page` document has no field that says which kind it is. `url-map.csv` `page_type` covers `home`/`service`/`post`/`blog-index`/`legal`, but not course vs service, contact or about. Suggest a `page.kind` field matching `SeoPage['kind']`.
- Contract request (C): course data (`educationalLevel`, `audience`, `teaches`, course instance, offers with `availability`/`validThrough`) and per-offer fields (`availability`, instalments, `soldByOrganization`) have no Sanity fields yet. `pricing` plans cover name/price/unit only. Today they exist only in the live JSON-LD.
- Contract request (C): `/o-mnie` `hasOccupation` has no Sanity home. Either add it to `person` or drop it.
- T18: `Base.astro` renders its own `<title>` and description. When routes use `<Seo>`, Base should take a head slot (or the `SeoPage`) instead, so the page keeps one `<title>`. FAQ answers must be flattened from Portable Text to plain text before they go into `page.faq`, and only for a `faq` block with `emitSchema !== false`.
- T17: once images are in Sanity, pass `width`/`height` on `post.image`, `primaryImage` and `ogImage`; the builders already emit them.
- Not covered by the six samples: `blogIndex`, `generic`, and services that reference another page's course (`/program-ai-dla-zespolu-sprzedazy`). The kinds exist and are type-checked; their parity is checked at gate G3 (T20).
