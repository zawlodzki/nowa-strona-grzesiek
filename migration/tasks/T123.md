# T123. Studio plugin: Otwórz podgląd button in the document header

## Goal

Editors in Structure have no direct way to jump from an open document to its preview in Presentation. Port the fixed version of the plugin from nowa-strona-ola, [PR #115](https://github.com/zawlodzki/nowa-strona-ola/pull/115) (merged 2026-10-16). The plugin adds an **Otwórz podgląd** button to the document header. The button opens the current document in Presentation, at the first `href` from the existing `presentationResolve.locations` in `apps/studio/presentation.ts`.

The history there is a warning. The first version ([#111](https://github.com/zawlodzki/nowa-strona-ola/pull/111) and [#113](https://github.com/zawlodzki/nowa-strona-ola/pull/113)) crashed the hosted Studio and had to be reverted ([#114](https://github.com/zawlodzki/nowa-strona-ola/pull/114)):

- `useFormValue` outside `FormValueProvider` crashed the hosted Studio.
- React #301 (too many re-renders) came from an unstable `onAction` passed to the field action resolver.

## Requirements

1. Build the intent helper in `apps/studio/presentation-intent.ts`. It returns an `edit` intent with `mode: presentation` and the first location `href`. With no slug or language it returns nothing, so the button stays hidden.
2. The header action reads the document from `useDocumentPane().value` (never `useFormValue`), keeps `onAction` referentially stable, and renders as a field action with `renderAsButton`. Mount it only for types that have a location resolver (`page`, `post`).
3. Add `node:test` tests:
   - an intent test;
   - a render test that mounts the action the way the Sanity 6.20 resolver does, with no `FormValueProvider`, and asserts a bounded render count (no infinite loop) plus the correct intent.

   Wire both tests into the studio `test` script.
4. Keep `autoUpdates: false` in `sanity.cli.ts`, which is already set. Do not bump `sanity`.
5. Studio only, with no public HTML change. Do not deploy Studio; Grzesiek deploys.

## Done when

- [x] Both tests pass. The render test fails on the unstable-`onAction` variant, so it really guards against React #301.
- [x] In a local `sanity build` plus `sanity dev`, opening a post and a page shows **Otwórz podgląd**, and clicking it opens Presentation on the right URL, with no error boundary. Prove this with screenshots. If login blocks this, record the blocker with a screenshot.
- [x] `pnpm --filter studio check`, `pnpm --filter studio build` and `tasks.py check` pass.
