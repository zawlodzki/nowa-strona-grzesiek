# T69. Deploy Sanity Studio from CI

## Goal

Studio is deployed by hand (`sanity deploy`), so the hosted Studio can lag behind the schema on `main`. Task files keep saying "do not deploy Studio", and the deploy then depends on someone remembering. In `nowa-strona-ola` a workflow deploys Studio and its schema after the quality workflow passes on `main`, for the exact commit that was checked.

## Steps

1. Read the current Sanity docs for deploying a Studio and its schema non-interactively (token type and scope, `--yes`, schema deploy, `deployment.appId`, auto-updates). Record the source.
2. Add `deploy-studio.yml`: triggered when the `CI` workflow completes successfully for a push to `main` in this repository; checks out that commit; skips if `main` has moved since; builds; deploys Studio to the existing host (`zawlodzki.sanity.studio`) and deploys the schema. Read-only repository permissions, a timeout, and a concurrency group that never cancels a running deploy.
3. Pin what the deploy targets in `apps/studio/sanity.cli.ts` (`deployment.appId`) so the workflow cannot create a second Studio. Decide on auto-updates and say why; `nowa-strona-ola` turns them off and pins the version.
4. Only run when something under `apps/studio/` changed since the last deployed commit, or explain why an unconditional deploy is fine.

## Human gate

The workflow needs a `SANITY_AUTH_TOKEN` repository secret with deploy rights. Ask the user to create it with the minimum scope and add it. The first automated deploy replaces the hosted Studio: ask before enabling the trigger, and coordinate with any open Studio task (T50, T51, T52, T53, T54) so a half-reviewed schema is not deployed.

## Done when

- [ ] The workflow exists and a dry run (`workflow_dispatch` with a no-deploy input) builds Studio from `main`.
- [ ] After the user's yes and the secret, one real run deploys Studio and schema; the hosted Studio shows the commit's schema. Evidence saved.
- [x] A run for an outdated commit skips the deploy (shown in the logs or by test).
- [x] `tasks.py check` passes; PR opened with status `review`.
