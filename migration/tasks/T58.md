# T58. State-change animations: press feedback, mobile nav, share popover, form status, tabs

## Goal

Add motion to five state changes in the site chrome that currently happen in one frame. The product scenes and the FAQ accordion already animate and are out of scope. `DESIGN.md` limits motion to scenes and state changes; this task stays inside that rule. It is CSS only, except three script lines in `Tabs.astro`.

The five changes were chosen with the `find-animation-opportunities` skill and specified with `improve-animations`. Scroll reveals, a hero entrance, page transitions, an animated TOC marker and hover zooms were considered and rejected. Do not add them.

## Plans

Each change has a self-contained plan in `migration/lanes/design/out/t58-animations/plans/`. Start with `README.md` there: it gives the order, the dependencies and the shared decisions.

| Plan | Change | File |
| --- | --- | --- |
| `001-press-feedback-scale.md` | Pill buttons scale to 0.97 while pressed | `ui/Button.astro`, `blocks/Pricing.astro`, `site/Header.astro` |
| `002-mobile-nav-open-close.md` | Mobile nav panel fades and slides open and closed | `site/Header.astro` |
| `003-share-popover-entrance.md` | Share popover scales in from its trigger | `post/SharePost.astro` |
| `004-lead-form-status-and-busy.md` | Form error message and busy state ease in | `forms/LeadForm.astro` |
| `005-tabs-panel-fade.md` | Tab panel content fades, selected tab eases | `blocks/Tabs.astro` |

Execute in the order 001, 002, 004, 003, 005. Plans 001 and 002 both edit `Header.astro`, so do them one after the other.

## Notes before starting

- The plans were written from the code at commit `2522982`, without running the site. On 2026-11-12 the six component files were identical on `main`. If a plan step no longer matches the code, stop and report under Handoff instead of improvising.
- Follow the `good-css` skill before editing CSS, as `AGENTS.md` requires. Use only the existing motion tokens in `apps/web/src/styles/tokens.css`. That file is not in `owns`.
- **Reduced motion.** The plans keep opacity fades under `prefers-reduced-motion: reduce` and gate only movement and scale. Existing code gates every transition. The user has not yet decided which rule to keep. Follow the plans, and record the choice under Handoff so it can be reversed in one line per component.
- **Unverified.** Whether Astro's scoped styles pass `@starting-style` through unchanged was not checked. Each plan has a step to inspect the built CSS.
- **Plan 005 may be cut down.** If the panel fade reads as a blink during fast scrolling through the pinned tabs, keep only the tab colour transition, as the plan says.
- T51 owns `Pricing.astro` and T53 owns `LeadForm.astro`. Both are `todo`. `tasks.py check` fails if this task is active at the same time as either of them, so do not claim it while one of them is claimed.
- Forms are an invariant in `AGENTS.md`. Plan 004 changes styles only: no markup, script, hidden field or Worker change.
