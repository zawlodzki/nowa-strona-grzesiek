# T65. Worker observability, form failure logging and declared secrets

## Goal

Lead forms go through the Worker (`/api/form` in `apps/web/src/worker/form.ts`). When Turnstile verification or the n8n forward fails, the visitor gets a 403 or 502 and nothing is recorded. `apps/web/wrangler.jsonc` has no `observability` block, so there are no Worker logs to look at. A lost lead is invisible. In `nowa-strona-ola` every Worker config enables logs and declares its required secrets.

## Steps

1. Read the current Cloudflare docs for `observability` (logs, sampling) and for declaring required secrets in the Wrangler config. Record the source and the Wrangler version that supports each key.
2. Enable logs in `wrangler.jsonc` and `wrangler.preview.jsonc`. Invocation logs off, sampling chosen so that form failures are always kept (log them explicitly, see step 3).
3. In `form.ts`, log one structured line for each failure branch: form key, branch (`turnstile`, `n8n`, `bad-request`), upstream status if any, and a request id. Log nothing the visitor typed: no e-mail, phone, message, attribution fields, IP or token. Add tests that assert the log line has only the allowed keys.
4. Declare the secrets the Workers need (`N8N_FORM_WEBHOOK`, `TURNSTILE_SECRET_KEY`; for preview `SANITY_API_READ_TOKEN`, `PREVIEW_AUTH_USER`, `PREVIEW_AUTH_PASSWORD`) so a deploy without them fails. Add `apps/web/.dev.vars.example` with names and placeholder values only. Regenerate `worker-configuration.d.ts` if the types change.
5. Verify with the `verify-web` skill under `wrangler dev`: force a Turnstile failure and an n8n failure against `form-mock-receiver.mjs`, and show the log lines. Never post to the production webhook.
