# T71. robots.txt: production allow, staging disallow, AI crawlers welcome

## Goal

T13 already ships a static `/robots.txt` that allows everything and names `https://www.zawlodzki.pl/sitemap.xml` (the sitemap index; there is no `sitemap-index.xml`). The Worker already adds `X-Robots-Tag: noindex, nofollow` on every non-production host. The preview Worker already answers `/robots.txt` with `Disallow: /`. The staging Worker (`zawlodzki-web` and `wrangler dev`) still serves the production body: `Allow: /` plus the production sitemap. `.claude/skills/verify-web/features/discovery-files.md` records that gap.

Make robots.txt host-aware, in line with the existing header rule, and state the AI-crawler policy in the file.

## Policy (defaults; do not reopen them)

- **Production** (`www.zawlodzki.pl` only, same host check as `apps/web/src/worker/index.ts`): allow crawling. `User-agent: *` / `Allow: /`. `Sitemap: https://www.zawlodzki.pl/sitemap.xml`.
- **Every other host** (staging `workers.dev`, localhost, apex, preview already covered): `User-agent: *` / `Disallow: /`. No `Sitemap` line. Do not point a non-production host at the production sitemap.
- **AI crawlers are allowed.** Grzesiek asked for easier agent access (T59: `/llms.txt` and the same URL plus `.md`). Do not add `Disallow` rules for GPTBot, ClaudeBot, Google-Extended, or similar. A short comment in the production file may point at `/llms.txt` and the `.md` versions. Markdown responses already send `X-Robots-Tag: noindex` (T59) so they are not indexed as HTML duplicates; do not also `Disallow` `*.md` in robots.txt.
- Do not invent a `/sitemap-index.xml` alias.

## Steps

1. Keep the production body in the existing renderer (`renderRobots` in `apps/web/src/pages/sitemap/_render.ts`) and extend its unit tests. Put the non-production body behind the Worker host check, in a new `apps/web/src/worker/robots.ts` (one-line hook from `index.ts`, the same pattern as other Worker helpers). Do not weaken the `X-Robots-Tag` rule. Do not change how the preview Worker serves `/robots.txt`.
2. Tests: production body (allow, sitemap URL, no AI Disallow, comment if you add one); non-production body (`Disallow: /`, no sitemap line); the Worker chooses the body from the `Host` header and leaves production responses without `X-Robots-Tag`.
3. Verify live with `verify-web` (`scripts/web.sh up|doctor|probe` on the assigned port, `wrangler dev --local`, never `astro dev`). Probe `/robots.txt` on the default local host (disallow, no sitemap) and with `--host www.zawlodzki.pl` (allow, sitemap). Update `discovery-files.md` and `robots-by-host.md` so the recipes match. Save the probe output in `migration/lanes/seo/out/t71-robots/`.
4. Always `scripts/web.sh down` at the end.
