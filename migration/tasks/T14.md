# T14. Form endpoint to n8n

## Goal

`/api/form` validates Turnstile and forwards every field to the existing n8n webhook.

## Inputs

- migration/00-inventory/webflow/forms.json
- migration/00-inventory/webflow-settings/SUMMARY.md

## Steps

1. Webhook URL only in the Worker secret `N8N_FORM_WEBHOOK`, never in the repo.
2. Redirect to `/podziekowanie-konsultacja` or `/podziekowanie-newsletter` on success.
3. Test with a local mock receiver; never call the real webhook from tests.

## Done when

- [x] Recorded mock payload contains all fields with the same names Webflow sends.

## Handoff

### What changed

- `apps/web/src/worker/form.ts` handles `POST /api/form?form=<key>`. The keys are the `formId` values from `contracts/blocks.json` (`main-contact`, `landing-contact`) plus `newsletter`. A table in the file maps each key to its Webflow form name (`main-contact-form`, `Landing Contact Form`, `Newsletter bottom CTA form`), its fields and its thank-you page.
- The Worker sends n8n the same envelope as the Webflow `form_submission` webhook (API v2): `triggerType`, then `payload` with `name`, `siteId`, `data`, `schema`, `submittedAt` and `id`. The existing n8n flow therefore needs no change. `data` has every field of the form under its Webflow name. Empty hidden fields go as `""`. Checkboxes go as `"true"`/`"false"`. Fields the form does not declare are dropped, and so is `cf-turnstile-response`.
- Order of checks: method, form key, a valid `email`, then Turnstile siteverify (secret `TURNSTILE_SECRET_KEY`, `CF-Connecting-IP` as `remoteip`), then the POST to `N8N_FORM_WEBHOOK`. Success returns `303` to `/podziekowanie-konsultacja` or `/podziekowanie-newsletter`. Errors return a short Polish text: 405, 404 (unknown form), 400 (bad email or body), 403 (Turnstile), 502 (n8n non-2xx or unreachable).
- `apps/web/src/worker/index.ts` routes `/api/form` to it before the static assets. `FormEnv` types both secrets without touching the generated `worker-configuration.d.ts`.
- `apps/web/src/worker/form-mock-receiver.mjs` is a local stand-in for n8n. It records each POST as a JSONL line and can answer with any status. `form.test.ts` (`node --test apps/web/src/worker/form.test.ts`, no new dependencies) runs the handler against it. It covers both thank-you redirects, all 37/34 fields, checkbox mapping, dropped fields, Turnstile rejection and n8n failure.

### Deviations

- The newsletter form on Webflow redirects to an absolute `https://www.zawlodzki.pl/podziekowanie-newsletter`. The Worker uses the relative path so staging stays on staging.
- The payload has no `formId`, `formElementId`, `pageId` or `publishedPath`. Webflow assigns these and nothing here can reproduce them honestly. If the n8n flow routes on one of them, it has to switch to `payload.name`. This is unverified, because I could not see the flow.
- The checkbox format `"true"`/`"false"` is inferred from Webflow's form script and not checked against a real Webflow webhook delivery. Submissions were not read (they hold personal data).
