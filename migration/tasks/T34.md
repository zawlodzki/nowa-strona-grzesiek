# T34. About page visual parity, shared testimonials and contact channels

## Goal

The user compared staging `https://zawlodzki-web.zawlodzki.workers.dev/o-mnie` with live `https://zawlodzki.pl/o-mnie` and listed six gaps. Fix them in the shared blocks, the page importer and (where needed) the testimonial schema, so every page that uses those blocks gets the fix. No route-specific CSS or `/o-mnie`-only overrides. Design scope is refine, not redesign: when in doubt, match live.

T33 (hero badge on mid/mobile, `Hero.astro`, branch `task/T33-hero-badge-responsive`) is in progress in parallel. Do not touch `Hero.astro` or `migration/lanes/design/out/hero-badge-responsive/**`. This task does not depend on T33.

## Causes found during triage (confirm, then fix)

Live `/o-mnie` is not six stacked feature sections. It is:

1. One `feature-section` whose grid is `.feature-grid-3.about` (`grid-template-columns: 1fr .5fr` on desktop, one column on small screens). All of the article lives in `.feature-content-wrapper` (tagline "O mnie", h1, then h2s and body in one flow, ending with the CTA "Porozmawiajmy o wdrożeniu" → `/kontakt`). The portrait (`img.image-2.about`, alt "Grzegorz Zawłodzki", asset `sylwetka tlo 600_compressed.webp`) is a sibling in the right column: `position: sticky; top: 4rem; max-width: 30%; display: block` on desktop, hidden on small screens. It sits beside the whole article, not next to the last heading.
2. A `contact-section` (`kontakt zawlodzki` / Contact Section in `blocks.json`): tagline "Kontakt", h2 "Jak się ze mną skontaktować?", two columns — "Social media" (GitHub, LinkedIn, X, YouTube, Instagram as brand icons) and "Bezpośredni kontakt" (email, phone, Signal, WhatsApp). There is no lead form on this page.
3. A `testimonials-section` (already a `testimonials` block in the contract): tagline "Co o mnie mówią", h2 "Opinie zadowolonych klientów", two quote cards. Live quote text already includes wrapping `"..."` marks. There are no author photos and no LinkedIn icons on the live cards today.
4. Then unchanged sections the user did not report: "Dane firmy", "Ostatnie wpisy", newsletter. Do not redesign them; keep them working.

Staging today: the importer's `SPLIT` on `feature`/`contentSection` cuts the about article at every h2 into six `feature` blocks, so section padding and Feature `.copy` gaps break the text into separate chunks (defect 2). The portrait is attached only to the last text segment, "Po czym poznasz że wdrożenie się udało?", and sits beside that last paragraph (defect 1; check `media_side()` if it also landed on the left). The contact section was imported as a `feature` with a single 48×48 GitHub logo and flattened channel text — no two-column social/direct layout (defect 3). The opinions were imported as a `contentSection` of `contentItem`s, not the shared `testimonials` block used on the homepage (defect 4). Quote text still has the live quotation marks; `Testimonials.astro` also injects typographic `„` `”` with CSS `::before`/`::after`, which will be one pair too many once the section is unified (defect 5, already visible as an extra mark in the current about markup).

`ContactForm.astro` always renders `LeadForm`. Channels, calendar and consultation render only when `variant === 'full'` (`/kontakt`). The about contact section needs the two-column channels layout from the same shared component, without a form, and `/` plus `/kontakt` must not regress.

The testimonial document already has `image` ("Zrzut rekomendacji", used by the `imageWall` variant) and `url` ("Źródło", currently wrapping the name). Do not overload those. Add new optional fields for the author portrait and the LinkedIn profile icon.

The importer already has `testimonials()`, `contact_form()`, `contact_channels()`, and a `testimonial-box` branch in `item()`. It also reports `testimonial-logo-dropped` when a card has an image and then drops it. Fix the mapping and the fields rather than inventing a new block type unless the contract truly cannot represent the layout.

## Steps

Defects reported by the user (1-6):

1. **The main photo must sit to the right of the whole article, like live.** Keep one about-article feature (do not split this Webflow section at its h2s). In the shared `Feature.astro`, add an opt-in layout that matches live: text column + sticky portrait on the right (~30% / `.5fr`), hidden on small screens, no empty gap when there is no image. Other Feature uses (homepage services, course modules, and so on) must keep their current layout. No `/o-mnie` route override.
2. **Paragraphs must read as one piece of text.** The large gaps come mainly from splitting one article into many `.section` Feature blocks. After the article is a single block, match live spacing between headings and paragraphs in that shared layout. Live often uses line breaks inside one `<p>` (`<br>‍<br>`) rather than large section gaps. Do not loosen or tighten global `.flow` in `apps/web/src/styles/layout.css` (that file is outside `owns`); scope typography in the components you own. Blog posts and other Feature sections must not regress.
3. **Fix the "Jak się ze mną skontaktować" section in the shared contact component.** Map the live contact section to `contactForm` (already in `blocks.json`). Extend `ContactForm.astro` so a channels-only (or equivalent) variant can render the two-column Social media + Bezpośredni kontakt layout without a lead form. Reuse the existing `channels` schema if it fits; add the smallest additive variant/field if it does not. Use correct `aria-label`s (live labels many icons "LinkedIn"). Keep the homepage landing form and the `/kontakt` full variant working. If a schema or `blocks.json` change is required, add a `decisions.md` row.
4. **Opinions must use the same testimonials section as the homepage.** The about opinions and the homepage opinions must both render through `Testimonials.astro` (and the same `testimonials` block). Fix the importer so a Webflow `testimonials-section` becomes a `testimonials` block with `testimonial` documents, not a `contentSection`. Remove any about-only or one-off opinions markup.
5. **One pair of quotation marks, not two.** Unify quote typography in the shared component so each quote has a single pair, consistent on `/` and `/o-mnie`. If the CMS/import text already includes wrapping quotes, strip them rather than painting a second pair in CSS, or drop the CSS quotes — pick the smallest change that matches live typography.
6. **Optional author photo and LinkedIn profile icon, hidden when empty.** In the `testimonial` document schema add optional `authorImage` (contentImage, required alt when set) and `linkedinUrl` (`https` URL). `Testimonials.astro` shows the portrait beside the attribution only when `authorImage` is set, and an "in" LinkedIn icon linking to `linkedinUrl` only when that URL is set. Empty fields render nothing and leave no gap. Wire the fields through `Sections.astro` / `site.ts`, Studio typegen and `verify-schema.mjs`. Map them in the importer when live HTML has a photo or a LinkedIn profile link on the card (today's `/o-mnie` cards do not). Do not silently drop a card image (`testimonial-logo-dropped`).
