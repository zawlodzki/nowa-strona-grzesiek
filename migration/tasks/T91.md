# T91. Load the c15t consent revocation fix

## Goal

Load the versioned c15t bundle that clears optional first-party cookies and Meta's `multiFbc` after consent is withdrawn.

## Done when

- [ ] The layout points to the publicly available corrected bundle.
- [ ] Chrome confirms the browser state and vendor requests across consent changes.

## Handoff

The Astro layout points to the new immutable bundle URL. Merge after the VPS
release serves the corrected bundle at that URL and its SHA-256 matches the
deployed container. Checking for HTTP 200 alone can pass against the previous
build because the query parameter is a cache key.

A Chrome run with the locally built widget on both public origins confirmed
that `multiFbc` is removed on marketing revocation and `_lfa` and
`_lfa_expiry` are removed on analytics revocation. The consent preference
remained after reload. Clarity's main script and the Leadfeeder script and
collector returned HTTP 200 after analytics consent using per-browser DNS
overrides. The system resolver on the test Mac returned loopback sinkhole
addresses for these domains.
