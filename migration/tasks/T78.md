# T78. Serve Markdown at canonical URLs via Accept

## Goal

An agent that requests Markdown at a canonical page URL receives the Markdown already generated by T59. Keep the site on Cloudflare Free.

## Requirements

- For GET and HEAD on canonical page URLs, serve the matching Markdown asset when Accept explicitly prefers `text/markdown`. Map `/` to `/index.md` and a page such as `/o-mnie` to `/o-mnie.md`. Return `200` and `Content-Type: text/markdown; charset=utf-8` at the original URL.
- Honor Accept quality values. Keep HTML for normal browser requests, wildcard-only requests, and requests that reject Markdown with `q=0` or prefer HTML. Use the existing response if the Markdown asset is missing. Preserve redirects, 404s, discovery files, and the form endpoint.
- Send `Vary: Accept` on both representations where negotiation is available. Keep `noindex` on direct `.md` URLs and keep the existing host and page indexing rules on canonical URLs. Do not copy the direct asset's `noindex` onto an indexable canonical page.
- Verify Cloudflare's cache behavior on staging. Keep HTML and Markdown separate if the edge caches either representation. Use an explicit cache rule or bypass if needed. Preserve the existing HTML cache behavior where possible. Production publication remains a separate step that needs approval.

## Done when

- [x] In Wrangler, the homepage, a service page, and a blog post serve Markdown with `Accept: text/markdown` and HTML with a browser Accept header. Both variants include `Vary: Accept`. HEAD matches GET status and representation headers, with no body.
- [x] The same URL returns the correct format when HTML and Markdown requests alternate in both orders on Cloudflare staging. Record response headers and cache status.
- [x] Redirects, missing pages, and discovery files keep their existing statuses and response types. Direct `.md` routes keep `noindex`. A staging page keeps `noindex, nofollow` in both formats.
- [x] Record the test commands and results in Handoff.
- [x] After the separately approved production release, rerun the HTTP probes and the Agent Readiness Markdown check.

## Handoff

The Worker checks the canonical HTML response before it looks up the T59 Markdown asset. Both formats send `Vary: Accept` and use their own ETags. Explicit HTML ties stay HTML. An explicit Markdown match wins a tie against an HTML wildcard. If Markdown is missing, the Worker returns the existing HTML response.

The negotiated Markdown response keeps the canonical page's indexing directives. The direct `.md` path keeps its own noindex. The existing staging host policy applies to both formats.

HTML keeps its original cache policy. Markdown uses a separate static asset path and sends `Cache-Control: private, no-store` to prevent shared caching of the negotiated response.

[Local HTTP evidence](../lanes/platform/out/t78-markdown-negotiation/local.tsv) records 83 requests through Wrangler. The home, service and blog routes alternate formats in both orders. GET and HEAD agree. A validator for the other format returns 200, and a matching validator returns 304. The same run covers redirects, discovery files, the form route, a missing Markdown asset, and page and host indexing rules.

[Staging baseline](../lanes/platform/out/t78-markdown-negotiation/staging-baseline.tsv) records 51 read-only requests to the existing deployment. The direct Markdown assets served Markdown. Canonical URLs served HTML for both Accept headers and reported cache HIT.

The [staging probes](../lanes/platform/out/t78-markdown-negotiation/staging.tsv) passed all 71 requests after `pnpm --filter web deploy:staging` deployed Worker version `eb6e5a7a-00fd-476a-b57b-a475f1fa52ab` from commit `19d2cbf`. All 48 alternating GET and HEAD requests across the home, service, and blog routes returned the requested format with `Vary: Accept` and `X-Robots-Tag: noindex, nofollow`. Cloudflare reported 24 Markdown HITs, 22 HTML HITs, and two HTML MISSes. HTML kept `public, max-age=0, must-revalidate`, and negotiated Markdown kept `private, no-store`. The HITs show the static asset cache at work for each format. No cache rule change was needed. The staging HTML response did not expose an ETag, so the validator test ran locally.
