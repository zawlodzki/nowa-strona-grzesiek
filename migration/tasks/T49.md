# T49. Redirects editable from Sanity

## Goal

Studio has a "Przekierowanie" document type (`redirect`: `from`, `to`, `status` 301), but no code reads it, so a redirect added in Studio does nothing. The user wants to manage redirects from Sanity.

The nine contract redirects from `contracts/url-map.csv` stay in `apps/web/src/worker/redirects.data.ts` and keep winning: they are gate-tested and must not depend on CMS content. Sanity redirects are additions on top.

1. At build time, read published `redirect` documents from the build dataset and make the Worker answer them with 301. A Sanity publish already triggers a Workers Builds deploy (T19), so an editor's change goes live with the next build.
2. Never let a CMS redirect break an invariant: skip, with a build warning, any rule whose `from` is a page the build serves, a contract redirect path, a reserved path (`/api/`, `/_astro/`), not a clean absolute path, or equal to its target. Uppercase paths stay 404 unless an editor adds that exact path.
3. No production Sanity writes in this task.

## Done when

- [x] A published `redirect` document produces a 301 from `from` to `to` on the Worker, on staging and production hosts alike.
- [x] Unsafe rules are skipped with a warning and covered by tests.
- [x] Contract redirects and all `keep` paths behave as before.
- [x] Proven through `wrangler dev` (verify-web), tests, `pnpm --filter web check` and `tasks.py check`.

## Handoff

**What changed**

- `apps/web/src/worker/cms-redirects.mjs`: an Astro integration. After the build it reads published `redirect` documents from the build dataset, filters them, and writes `dist/_redirects` (`<from> <to> 301` per line). Workers static assets applies that file when the Worker calls `env.ASSETS.fetch`, so `index.ts` needed no change and is dropped from `owns`.
- `astro.config.mjs`: registers the integration.
- `cms-redirects.test.mjs`: the filter and the file format.
- `.claude/skills/verify-web/features/redirects-cms.md`: how to check it.

**How it behaves**

- Order: contract redirects (`redirects.data.ts`, from `url-map.csv`) run first in the Worker; Sanity rules apply after, inside the asset layer.
- A rule is skipped with a build warning when its source is a live page, a contract redirect path, `/`, under `/api/` or `/_astro/`, not a clean path (query, wildcard, space, `//`), equal to its target, a duplicate (newest wins), or when its target is itself redirected. The target must be site-relative.
- Matching is exact and case-sensitive, so uppercase paths stay 404 unless an editor enters that exact path. The query string is kept. The trailing-slash form of a source is 404.
- An editor's change goes live with the next build, which the existing Sanity webhook triggers on publish (T19). **The live webhook does not fire for `redirect` yet.** Checked read-only on 2026-11-12 with `sanity hooks list` and `hooks logs`: one webhook, "Cloudflare staging on published content", dataset production, POST. The CLI does not print the filter, but the delivery log matches the documented one: when a `course` and a `service` document were published together at 10:11Z, only the service produced a delivery. The documented filter lists neither `course` nor `redirect`. `apps/web/src/preview/README.md` now lists both; the webhook itself has to be edited in Sanity (manage → API → Webhooks) by the user or on the user's yes.

**For the editor**: in Studio, "Przekierowanie" → new document → "Ze ścieżki" `/stary-adres`, "Do ścieżki" `/nowy-adres` → Publish. Skipped rules show only in the build log, not in Studio.

**Deviations and follow-ups**

- The six Webflow redirects were not copied into Sanity. They are contract rows and stay in code; a Sanity copy would be skipped as a contract path.
- Studio does not warn about a source that is a live page. A validation rule in `apps/studio/schemaTypes/documents.ts` would, but that file is in T47's open PR.
- No Sanity writes. The dataset has no `redirect` documents, so the build writes an empty file.

**Evidence** (wrangler dev --local through verify-web, port 8798, build on the production dataset)

- Build log: `[cms-redirects] 0 redirect(s) from Sanity, checked against 117 pages`. `dist/_redirects` exists and is empty.
- With two rules appended to the built file: `/stary-testowy-adres` → 301 `/kontakt`; with `?utm_source=x` → 301 `/kontakt?utm_source=x`; `/Stary-Test` → 301 to its target with the target's own query; `/stary-test`, `/STARY-TESTOWY-ADRES` and the trailing-slash form → 404.
- Unchanged: `/konsultacja` → 301 `/wspolpraca`, `/search` → 301 `/blog`, `/kontakt` 200, `/kontakt/` → 301, `/Kontakt` 404, `/nope` 404, `/_redirects` 404.
- Local host adds `X-Robots-Tag: noindex, nofollow` to the redirect; `Host: www.zawlodzki.pl` does not.
