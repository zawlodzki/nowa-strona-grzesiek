# T19. Preview Worker, visual editing and deploy hook

## Goal

Editors see drafts before publishing; publishing triggers a rebuild.

## Inputs

- migration/PLAN.md section 3

## Steps

1. SSR preview Worker with a Sanity read token, noindex and access protection.
2. Presentation tool in Studio.
3. Sanity webhook to the Workers Builds deploy hook.

## Done when

- [ ] Editing a draft shows in preview; publishing changes staging within 5 minutes.

## Handoff

**What changed.**
- `apps/web/src/preview/` is a separate Astro SSR application using the existing content parser, route table and renderer. Each authorized request reads Sanity drafts without a CDN or process cache. Incomplete unrelated drafts are excluded at the preview boundary. An incomplete selected page gives a safe 422; an unavailable upstream gives 502.
- `wrangler.preview.jsonc` configures `zawlodzki-web-preview`. The Worker authenticates before serving HTML or assets, adds noindex and private/no-store headers to every response, disallows robots, and rejects form POSTs. Runtime bindings hold the read token and auth credentials.
- Studio imports `presentation.ts` with PL/EN page and post locations. Sanity's preview-secret enable endpoint creates a one-hour signed HttpOnly cookie bound to the origin and dataset. Basic Auth remains available for direct access. Editable text carries source maps for overlays.
- `site.ts` exposes a request reader while its production loader stays cached. `RouteView.astro` accepts an explicit Site and preview noindex flag. Production remains static.
- README.md documents deployment, the initial Workers Builds Git connection, the Sanity webhook filter and the timed publish check. The hook URL belongs only in the external webhook configuration.

**Scope approvals.** The owner approved adding the Astro and Studio configs, package manifests, lockfile, shared Site loader and RouteView to `owns` on 2026-10-22.

**Verification.**
- `pnpm --filter web preview:test` passed 14 tests. `pnpm check` passed, including schema validation. Web TypeScript and both application builds passed. Existing Worker and SEO tests passed 33 tests with one inventory-dependent skip.
- Real local Wrangler probes passed for 401, 200, 400, 404, 405, assets, HEAD, robots and no-store/noindex headers. The token was absent from HTML and browser JavaScript.
- A real unpublished development draft changed from revision one to revision two in the same running Worker without rebuilding. The dedicated development fixture remains unpublished.
- A real Studio preview secret validated and opened a top-level preview page. The iframe did not finish loading in the browser session, so field navigation and automatic refresh are not claimed.
- verify-web through the static Worker passed its healthcheck and confirmed production-host headers, a query-preserving 301, uppercase 404 and asset delivery after the preview build.
- Full commands and sanitized request results are in `apps/web/src/preview/verification.md`.

**Deviations and remaining acceptance.**
- The adapter initially wrote a deploy redirect in the web root, which made ordinary Wrangler commands select preview. The preview now has its own Astro root, and the static Worker was retested successfully.
- Basic Auth alone did not complete the local iframe flow. Added Sanity's standard secret-validation handshake with signed sessions. The final iframe acceptance still needs verification on the deployed origins.
- No deployment, published-content mutation, production dataset write, Workers Builds connection or webhook configuration was performed. These external actions require owner approval under AGENTS.md. The existing staging Worker is not connected to Git, and no Studio is deployed.
- The Done when box remains unchecked until a real edit works in Presentation and an approved publish reaches staging in less than five minutes.
