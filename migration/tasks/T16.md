## Handoff

**What changed.**
- `migration/tools/import/pages.py` has three subcommands, like T15's `posts.py`. `build` writes `page`, `logo` and `testimonial` documents to `migration/lanes/migration/out/dist/pages.ndjson` (gitignored) and `pages-report.json`. `import <dataset>` runs `sanity dataset import --replace` and refuses `production`. `snapshot <dataset> <out>` hashes what the dataset stores.
- The section order and block type come from the Webflow page trees (`components.json` pageSections) through the `match` rules in blocks.json. The content comes from the live HTML section at the same position. Legal pages have no tree and are read from the live HTML. Thank-you pages come from `page-content/`. The 404 page has no source in the inventory, so it uses the copy `apps/web` serves today.
- `_id` is `page-<webflowPageId>` via `lib.ids.doc_id`, so T15's 243 weak post links to pages now resolve. Logos are `logo-<sha1(url)>` and testimonials `testimonial-<sha1(quote)>`, so a logo or quote shared by several pages is one document.
- The `development` dataset holds 28 pages, 36 logos and 2 testimonials (66 documents). Nothing was written to production.
- The report lists every lossy mapping per page (`issues`) and, per Webflow section, the source words no block field carries (`textLoss`).

**Mapping decisions and deviations.**
- A Webflow section often holds several logical blocks (two timeline steps and a "Co dostajesz" grid in one section). Feature and Section sections are split at each h2, or h3 after a tagline. The first part keeps the matched block type. A later part becomes a contentSection when it is a list or grid without media, else a feature. The build emits 100 features and 49 contentSections in total.
- A section with a stat-card grid and a checklist becomes two contentSections, so neither list is lost.
- The Webflow tree for `/szkolenie-i-wdrozenie-salesforce` has a Testimonials section that the live page does not render. It is skipped (`tree-section-not-rendered`). Any other mismatch between tree and HTML stops the build.
- Four "Testimonials Section" sections on the AI pages are rows of tool logos, not recommendations. They are imported as `logoStrip` (variant tools) with the subtitle as title (`testimonials-as-logos`).
- Diagram keys are read from the embed's CSS id and accepted when blocks.json or T11's `apps/web/src/components/diagrams/registry.ts` lists them. 67 sections got a diagram. All 52 registry keys landed on exactly the pages the registry's `diagramPages` names, and 0 keys were unknown.
- The Sales Atlas tab grid (9 layers) is a contentSection with one item per layer. The tab summary and the "działa / nie działa / od czego zacząć" pane text are flattened into `text`, with the pane's first link as `link` (`tabs-flattened`, 6 further pane links in `tab-link-dropped`).
- Legal text lives in a Webflow HTML embed (`div.zw-legal`). Embeds holding prose are read as content. Embeds with scripts or no prose stay code. One table inside a numbered list item becomes its own table block between list runs.
- `/kontakt` has "Contact Section" plus "Contact Section Details". They merge into one `contactForm` (`variant: full`, `showDetails: true`).
- Home anchors `#crm #ai #automatyzacja #asana` are kept as `anchorId`.
- The page `title` is the hero H1, else the first H1 of the page, else the url-map title. SEO title and description come from `pages.json` unchanged.
- Sales Atlas fix (user decision 2026-10-21): `CONTENT_FIXES` replaces "250 osób" with "500 osób" and fails the build unless each phrase appears exactly once. SEO description, the "Czym Sales Atlas System nie jest" item and the FAQ answer now say 500. The blog post is not touched.
- Python stdlib, reusing T15's `lib/` read-only.
