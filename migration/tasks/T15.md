# T15. Importer: blog posts HTML to Portable Text

## Goal

Idempotent import of 80 posts into Sanity.

## Inputs

- migration/00-inventory/webflow/cms/
- migration/contracts/blocks.json portableText

## Steps

1. Deterministic `_id` from the Webflow item id.
2. HTML to Portable Text with table, figure, embed, codeBlock, download objects. FAQ pairs to an array. `json-ld-extra` parsed into typed schemaExtras. Dates as datetime.
3. Write to a non-production dataset first.

## Done when

- [x] Running the import twice gives identical documents.
- [x] 80 of 80 posts, 0 references to website-files.com after T17 rewrites.

## Handoff

**What changed.**
- `migration/tools/import/posts.py` has three subcommands. `build` turns `cms/blog.items.json` into `post` documents in `migration/lanes/migration/out/dist/posts.ndjson`, plus `posts-report.json`. `import <dataset>` runs `sanity dataset import --replace` and refuses `production`. `snapshot <dataset> <out>` hashes what the dataset actually stores.
- `migration/tools/import/lib/` is shared with T16 and T17. `ids.py` holds deterministic `_id`s (`post-<webflowItemId>`, `page-<webflowPageId>`) and hash-based `_key`s. `html_pt.py` converts HTML to Portable Text. `links.py` resolves hrefs through `url-map.csv` and `pages.json`. `assets.py` turns a source URL into an image value.
- `posts-report.json` is tracked. It holds counts, the ndjson sha256 and every data issue by post.
- The `development` dataset now holds the 80 posts and 245 image assets.

**Deviations.**
- Python stdlib instead of `posts.mjs`. `html.parser` needs no new dependency, and the root lockfile is not in `owns`. The source uses 23 tags, and any tag outside that set stops the build.
- The ndjson is gitignored (`dist/`). It reproduces whole inventory records and the repo is public. `build` regenerates it byte for byte. The report records its sha256.
- Images not yet in T17's `asset-map.json` go through `_sanityAsset: image@<url>`. Sanity names an asset by its content hash, so T17 uploading the same file lands on the same asset id. Once the map exists, `build` emits `asset._ref` for every URL it covers.
- `build` fails if any post body or FAQ answer loses text against its source HTML. All 80 pass.

**Mapping decisions.**
- Slug `/blog/<slug>` (full path, as the schema asks). `kind` comes from `typ-wpisu`. 15 empty values are imported as `blog`.
- `cta` is `{label: cta-text, href: /kontakt}`. The live template renders cta-text as the heading and a fixed "Umów konsultację" button to `/kontakt`. The renderer should keep the fixed button text.
- Own-site links become `internalLink`s: 486 to posts and 243 to pages. Page references are `_weak` to `page-<webflowPageId>`, because pages come from T16. Links with a fragment or query keep an absolute `link`, because `internalLink` has no anchor field. 0 internal links were unmapped.
- A paragraph holding only `files.zawlodzki.com` links becomes `download` objects (2).
- `json-ld-extra`: SoftwareApplication nodes map to `softwareMentioned` and ItemList elements to `itemList`. HowTo (6 posts) and `offers` (2) are dropped on purpose (AGENTS invariant, no typed field). `darmowy-crm` had two ItemLists, now merged into one `itemList`.
- Scribe iframes have no title. Their `embed.title` is derived from the Scribe URL (3).

**Evidence.**
- Two imports give identical documents. `snapshot development` after import N and after import N+1 both give sha256 `be86b19b298f3468228570a014747f01ef928b4308c39fc38a69f25c07a6bdba`, with all 80 per-document hashes equal. The dataset kept 245 image assets across four imports, so nothing was duplicated. Two builds give a byte-identical ndjson (`ndjsonSha256` in the report).
- 80/80 posts, with `"websiteFilesRefs": 0` and `"sanityAssetPlaceholders": 0` in the snapshot. Every image is a Sanity asset. T17 still owes the asset map and the missing alt text.
- verify-web, through `wrangler dev`: a throwaway route rendered each imported post with T10's `RichText` and `PortableText`, then was deleted and never committed. 80/80 returned 200. Element counts on the served HTML match the source across all posts: img 172/172, table 251/251, iframe 3/3. `PortableText` throws on an unresolved image, and the build succeeded. At 375px in a browser, `scrollWidth` equals the viewport. Only tables scroll, inside their own region.
- `sanity documents validate` on development shows these errors: 243 "Referenced document must be published" (page links, fixed when T16 imports pages with these ids), 18 SEO descriptions over 160, 7 SEO titles over 60, and 27 empty alts (15 body, 6 mainImage, 6 thumbnail). They are listed per post in `posts-report.json`. Fixing the SEO copy is an editorial call, so it was imported unchanged.

**Follow-ups.**
- Contract request: `table.rows[].cells` is `string[]`, so 50 links and 139 bold or italic runs inside table cells become plain text. Proposal: cells as Portable Text spans (`{_type: tableCell, content: block[]}`).
- T16: use `lib.ids.doc_id('page', <webflowPageId>)` for page `_id`s, so the 243 weak references from posts resolve.
- T17: write `asset-map.json` as `{"<source url>": {"assetId": "image-…", "alt": "…"}}` (the shape `lib/assets.py` reads). Rerunning `posts.py build` and `import` then fills in drafted alts.
- Owner: 25 posts have SEO title or description over the schema limit. The list is in the report (`seo-title-too-long`, `seo-description-too-long`).
- verify-web: `web.sh shot --width 375` crops the right edge, while a real 375px viewport renders correctly. Probably the headless window width. Not fixed here (not owned).
