# T81. Testimonial logos respect the logo invert setting

## Goal

The owner enabled "Odwróć kolory" (`invert`) on the Smmash `logo` document in Sanity. The logo strip shows it correctly, but the testimonials section on /szkolenie-i-wdrozenie-asana still shows the logo without inversion. Testimonials must respect the same Sanity setting.

## Context

- `LogoStrip.astro` applies `invert(1) grayscale(1)` when `logo.invert` is true.
- A `testimonial` document has its own `image` field ("Zrzut rekomendacji"), rendered as `.logo` in `Testimonials.astro`. For Smmash it uses the same Sanity image asset as the Smmash `logo` document, but nothing carries the `invert` flag across.

## Requirements

- When a testimonial image uses the same image asset as a `logo` document with `invert: true`, render it inverted in the testimonials section, with the same visual treatment as the logo strip on that background.
- Use the `invert` value from Sanity as the source of truth. Do not hard-code company names.
- Do not change the Sanity schema and do not write to any Sanity dataset. If a clean fix truly needs a schema field or reference, stop, set status blocked and explain why.
- Testimonials without a matching inverted logo look exactly as before.

## Done when

- [x] On /szkolenie-i-wdrozenie-asana in `wrangler dev --local`, the Smmash testimonial logo is inverted and readable. Show screenshots of production (current) vs the branch, for the testimonials section and the logo strip.
- [x] A test covers the asset-match behavior, including the case without a match.
- [x] `pnpm test`, the build and the e2e suite pass. Record commands and results in Handoff.

## Handoff

### What changed

- `apps/web/src/lib/sanity/testimonial.ts` adds `invertsLikeLogo(logos, image)`. It returns true only when some `logo` document has `invert: true` and the same `image.asset._ref` as the testimonial image. It matches no company names.
- `apps/web/src/lib/sanity/Sections.astro` passes `invert` on each resolved testimonial that has an image, using `site.logos` (already loaded by the site query). No query or schema change.
- `apps/web/src/components/blocks/Testimonials.astro` adds `invert?: boolean` to `ResolvedTestimonial` and the class `invert` on `img.logo`. `.logo.invert` gets `filter: invert(1) grayscale(1)`, the logo strip's resting filter for `.difference`. Testimonials without a match render the same markup and styles as before (`class="logo"`, filter `none`).
- `apps/web/src/lib/sanity/testimonial.test.mjs` covers the unit behavior: a match with an inverted logo; the same asset on a logo whose `invert` is false or unset; an asset no logo uses; a testimonial without an image or asset.
- `apps/web/e2e/pages.spec.ts` adds a Worker-served check on `/szkolenie-i-wdrozenie-asana` (match, Smmash) and `/` (no match, AdTelier). Each testimonial logo has computed filter `invert(1) grayscale(1)` exactly when its asset is inverted (`li.difference`) in that page's logo strip, and `none` otherwise.
- `migration/lanes/web/out/t81-testimonial-logo-invert/` holds the screenshots and `compare.mjs`, the Playwright script that made them (`node compare.mjs <apps/web dir> <out dir>` with verify-web up on 8790).

### Deviations

- The opacity .65 from the strip is not copied. The other testimonial logos (AdTelier) render at full opacity with no grayscale, so a faded Smmash would look out of place. Only the filter is shared.
- The `imageWall` variant shows full recommendation screenshots and does not get the class.
- LogoStrip's name fallback (`whiteByName`) is not mirrored, per "Sanity `invert` is the source of truth".
- www.zawlodzki.pl already serves the Astro build, so the production screenshot is the bug as reported, not Webflow.
