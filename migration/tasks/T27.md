# T27. Global navigation and footer

## Goal

Render `siteSettings.nav` and `siteSettings.footer` on every page, including the mobile nav. Match the live chrome with the refine rules in `DESIGN.md`. Do not edit `Base.astro`.

This task depends on T26. T26 mounts `<Header />` and `<Footer />` and passes `language` and `pathname`. It also leaves the two files as empty landmarks. Replace those landmarks. Do not take `Base.astro` back. If the props are missing, stop and write that in the Handoff.

The `siteSettings` query lives in this directory, for example `apps/web/src/components/site/settings.ts`. T20 still owns `apps/web/src/lib/sanity/**`, so the query does not go there.

## Inputs

- `apps/studio/schemaTypes/documents.ts` for `siteSettings`, and `apps/studio/schemaTypes/objects.ts` for `link`
- `DESIGN.md`, the Navigation section, and the `nav-link` tokens
- The T26 mount in `apps/web/src/layouts/Base.astro`
- The public site `https://www.zawlodzki.pl/`, read only

## Steps

1. Load `.claude/skills/good-css/SKILL.md` before any CSS. Keep the styles inside `apps/web/src/components/site/`. Do not edit `apps/web/src/styles/**`. T08 owns that tree. A missing `siteSettings` document renders the empty landmarks and does not throw, so a build with no such document still succeeds.
2. Read the `siteSettings` document for the `language` prop. Render each link `label` and `href` from that document. Do not hardcode the live menu. The header is the sticky Paper bar from `DESIGN.md`. The logo points at `/` for PL and at `/en/` when `language` is `en`. Below 992px the links collapse into a Paper sheet behind a control that opens and closes. At 1280 the links are visible without that control. The current item uses `aria-current` and Ink. Do not use Webflow blue `#0082f3`.
3. On 2026-10-23 the live header puts a primary pill at the right of the desktop nav, and the mobile sheet repeats a contact link. Use the `siteSettings.nav` items for both. If the rendered list differs from the live header, record the difference in the Handoff. Do not add a schema field. The same day's live page has a promo line above the nav. `siteSettings` has no field for it. Leave the promo line out.
4. Render `siteSettings.footer` in the footer. The live footer HTML has one control, label `Zarządzaj zgodami`, with `data-c15t-open`. If that label is already a footer link, put the attribute on that control. If the document has no such link, add that one control. Do not add a second one.
5. Prove the chrome with verify-web at 1280 and at 375. Do not deploy. This task does not close T20. T20 still owns the open crawl differences, including the missing chrome, until its own gate is repeated.

## Done when

- [ ] A Worker started with verify-web serves `/`, `/kontakt`, and `/szkolenie-i-wdrozenie-pipedrive` with a header and a footer. Shots at 1280 and at 375 exist for each of those paths. The Handoff quotes the visible labels and hrefs from the DOM and names the shot files.
- [ ] At 1280 the nav links are visible. At 375 they sit behind a control, and that control opens and closes from the keyboard. The collapse starts at 992px.
- [ ] The labels and hrefs come from `siteSettings` for the page language. The footer DOM contains exactly one `[data-c15t-open]`.
- [ ] A test or a build where the query returns no `siteSettings` document still succeeds and still emits the empty landmarks.
- [ ] There was no deploy to staging or production, and no write to Sanity.
