# T32. Sales Atlas System page parity, hero badge and layer tabs

## Goal

The user compared staging `https://zawlodzki-web.zawlodzki.workers.dev/sales-atlas-system` with live `https://zawlodzki.pl/sales-atlas-system` and listed four gaps. Fix them in the shared blocks and in the page importer, so every page that uses the same block gets the fix. Design scope is refine, not redesign: when in doubt, match live.

Board note: T32 edits files that T31 (PR #50, still open) also owns (`Hero.astro`, `ContentSection.astro`, `Sections.astro`, `_ds/**`). `tasks.py check` forbids two active tasks owning the same path and forbids claiming a task whose dependency is not done, so T32 depends on T31. The work branch `task/T32-sales-atlas-parity` is stacked on `task/T31-homepage-visual-parity` and the PR targets `main` as a draft that merges after #50. The claim (`status: claimed`) lands on `main` once T31 is done; until then this task is not in `ready`, so nobody else can pick it.

## Steps

Defects reported by the user (1-4), with causes found during triage:

1. **Hero has no badge over the photo.** Live uses the Webflow component "Hero zawlodzki badge": an `img.badge-naroznik` inside `.foto-hero-wrapper{position:relative}`, `position:absolute; z-index:2; bottom:-60px; left:-40px; width:130px` (mobile: `width:60px; bottom:-20px; left:-15px`). On this page the image is `sales-atlas-system-pion.svg` (alt "Sales Atlas System badge"). The same component on `/szkolenie-i-wdrozenie-salesforce` shows the Salesforce logo (`Salesforce.com_logo.svg.webp`, 200 px desktop, 70 px mobile). Staging: the `hero` schema has `variant: 'default'|'badge'` and `badges: string[]` (text chips) but no image field; the importer sets `variant: 'badge'` on both pages and drops the image; `Hero.astro` ignores it. Add an optional image badge to the shared `hero` block (additive, optional schema field with required alt when set; size option only if needed to match both live sizes). `Hero.astro` overlays it on the photo like live and renders nothing when no badge is set in the CMS. Map `.badge-naroznik` in the importer so a re-import fills it. Update `blocks.json` and add a `decisions.md` row.
2. **Keep the hero CTA that staging added** ("Umów bezpłatną konsultację", `Hero.astro` falls back to `consultation`). Do not remove it.
3. **"Dziewięć warstw" must be clickable panels, not stacked text.** Live is a Webflow vertical tabs widget (`.tabs-vertical.w-tabs`): left menu `.tabs-menu-vertical` (35%) of nine `a.tab-vertical` (h3 "01 Diagnoza" + summary paragraph; radius 6px, padding 16px 24px, hover background neutral-20, current background secondary-10), right `.tabs-content-vertical` (65%) with the active `.panel-warstwy` card (white, 1px neutral-40 border, radius 20px, padding 40px, shadow `0 8px 24px #00000014`) holding a "Po czym poznać, że działa" card (bg `#ebedfa`, border `#d8dcf5`), a "Po czym poznać, że nie działa" card (bg `#edf0f3`, border `#dde1e6`), a tagline "Od czego zacząć" and paragraphs with one or two inline links. Webflow fades panes (300 ms in, 100 ms out). On small screens the menu goes full width and the content moves above it (`order:-1`). Staging: `tab_items()`/`content_section()` in `migration/tools/import/pages.py` flatten the tabs into a `contentSection` list, joining pane text into `item.text`, keep only the first link of each pane (`tab-link-dropped` x6), and take the wrong heading and tagline (h2 "01 Diagnoza", tagline "Od czego zacząć") because the section has no `.section-title`. Build a reusable tabs block (new schema object, new `Tabs*.astro` component registered in `Sections.astro`, generic field names, not Sales-Atlas-specific), and map Webflow `w-tabs` to it in the importer with all links kept. Accessibility: WAI-ARIA tabs pattern (`tablist`/`tab`/`tabpanel`, `aria-selected`, `aria-controls`, roving `tabindex`, arrow keys for the vertical list plus Home/End), visible focus, works without JavaScript (all content reachable), and no animation under `prefers-reduced-motion`.
4. **Test list is at the end of the "Sprawdź, czy masz już system" section.** Live order: section title (tagline, h2, intro paragraph), then `ol.list-2` with three plain numbered items ("Weź 10 ostatnich leadów…", "Odtwórz z systemu…", "Zrób to bez pytania…"), then two paragraphs ("Jeżeli trzeba było kogoś dopytać…", "Drugi test…"). Staging: `content_section()` takes the `li`s as `items` and all three paragraphs as `intro`, and `ContentSection.astro` renders intro before items, so the list lands after both closing paragraphs and its items render as h3 headings. Fix generically so content keeps DOM order and a plain ordered list renders as a numbered list (for example an optional portable-text field after the items, or plain lists kept inline in portable text; pick the smallest schema change). Other pages must not change unless they had the same defect.

Content: the fixes need new data for this page (tabs block, list order) and for the two hero badges. Do not write to any Sanity dataset (production writes are a human gate). Instead:

- Run the fixed importer offline and write the proposed documents for the changed pages to `migration/lanes/design/out/sales-atlas-parity/` (NDJSON or mutation JSON, no secrets), plus a diff of every page whose import output changed versus the current import.
- For local proof, add an env-gated data overlay (for example in `client.ts`/`site.ts`, read only when an explicit env var points at that file; never in CI or deploy) or use `_ds` fixtures, so `wrangler dev` renders `/sales-atlas-system` with the proposed data.
- Write under Handoff the exact Studio steps the user must do (page, block, field, asset, alt), and the exact patch to apply if he approves a production write.
