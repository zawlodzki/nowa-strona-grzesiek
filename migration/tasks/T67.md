# T67. ESLint and Prettier: config and CI, no mass reformat

## Goal

This repo has no linter and no formatter. `nowa-strona-ola` runs ESLint (typescript-eslint, eslint-plugin-astro, zero warnings, no explicit `any`) and Prettier with the Astro plugin in CI. Several agents write code here, so style drifts between files.

Add the tooling without touching code that other tasks own.

## Steps

1. Add ESLint with typescript-eslint and eslint-plugin-astro, and Prettier with prettier-plugin-astro, as root dev dependencies. Check the current versions and their peer ranges before choosing.
2. Ignore generated and vendored paths: `dist`, `.astro`, `.wrangler`, `.sanity`, `worker-configuration.d.ts`, `sanity.types.ts`, the agent tool folders, `migration/lanes/**/out/**`, `migration/00-inventory`.
3. Run both and record the findings by rule and by file in `migration/lanes/platform/out/t67-lint/`.
4. Do not reformat or fix files outside `owns` in this task. For ESLint, start from the recommended sets; turn a rule into an error in CI only if the codebase already passes it, and list the rest as warnings with counts. For Prettier, add `format` and `format:check` scripts but do not add `format:check` to CI yet.
5. Add `pnpm lint` to CI.
6. Write the follow-up under Handoff: which rules to promote, and when to do the one-time format commit (a moment with no open task branches, so nobody has to rebase over it).
