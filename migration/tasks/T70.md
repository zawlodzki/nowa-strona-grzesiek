# T70. Operations guide: deploys, secrets, rollback, who to call

## Goal

How the site is built, deployed and repaired is spread over task handoffs and `apps/web/src/preview/README.md`. There is no root `README.md`. `nowa-strona-ola` keeps a README with checked commands and a `CLOUDFLARE-DEPLOYMENT.md`. After the migration ends, the task board stops being the place people look.

Write one short guide that a person or an agent can follow at 2 a.m. without reading the task history.

## Steps

1. `migration/lanes/platform/out/OPERATIONS.md`, with these sections, each a few lines and a command:
   - What runs where: Workers (static, preview), Studio, Sanity project and dataset, n8n, c15t, DNS. Names only, no secret values, no webhook URLs.
   - How a code change reaches production, and how a content publish does.
   - Secrets: name, which Worker or workflow uses it, where it is set. Values never.
   - "A publish did not appear": how to read the build, re-run it, and what the monitor from T63 tells you.
   - "The form is losing leads": where the logs from T65 are and what each failure line means.
   - Rollback of a bad deploy (Wrangler rollback or redeploying the previous commit; check the current docs and test the command with a dry run).
   - Restore of content: link to `migration/lanes/cms/out/backup/RESTORE.md` from T64.
   - Environments from T66 and how to try a change on staging.
2. Root `README.md`: what the repo is in five lines, how to install, build, test and run locally, and links to `AGENTS.md`, `migration/PLAN.md` and the operations guide. Every command in it must have been run in this session.
3. Remove nothing from `apps/web/src/preview/README.md`; link to it.
