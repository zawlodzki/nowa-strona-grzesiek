# T122. Studio plugin: Do uzupełnienia panel for [[TODO: …]] markers

## Goal

Agents leave gaps in drafts as `[[TODO: text]]`. Editors cannot see a list of them, and publishing does not warn about them. Port the plugin built for nowa-strona-ola in [PR #110](https://github.com/zawlodzki/nowa-strona-ola/pull/110) (merged 2026-10-15). The plugin adds a **Do uzupełnienia** panel next to the table of contents that lists every marker in the document. Clicking a marker opens its block. Publishing still succeeds, with a warning.

Read the Ola implementation first (`studio/components/editorial-markers.tsx`, `studio/schema-types/shared/editorial-markers.ts`, `tests/unit/editorial-markers.test.ts`) and adapt it to this repo's schema. Do not copy Ola's paths, npm, or vitest setup.

## Requirements

1. Write a pure scanner in `apps/studio/lib/editorial-markers.ts`. It walks the Portable Text spans in a document and returns every `[[TODO: …]]` with its path, the same way Ola's version does, including the older ALL-CAPS labels if they appear in our content. Use one walk over the strings in a block, not a per-block-type field registry.
2. Show the panel on `post` documents (`body`, plus `faq[].a`) and on `page` documents, including the legal pages in the "Strony prawne" list (Portable Text inside `sections`). Place it next to the existing `sanity-plugin-table-of-contents` inspector. Use the same `onFocus` / `onPathOpen` behaviour so that a click opens the block.
3. Add a non-blocking validation warning on those fields when markers exist. Publishing must not be blocked.
4. Add `node:test` tests for the scanner in `apps/studio/lib/editorial-markers.test.mjs` and wire them into the studio `test` script.
5. Studio only. Public HTML, GTM, consent and analytics do not change. Do not deploy Studio and do not write to the production dataset; Grzesiek deploys.
