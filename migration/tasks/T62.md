# T62. Build output gate: check dist for SEO invariants and size budgets

## Goal

A Sanity publish triggers Workers Builds directly (`apps/web/src/preview/README.md`, "Published-content rebuild hook"). Whatever `pnpm build` produces is deployed. The SEO invariants in `AGENTS.md` are checked by hand per task (`crawl.mjs`, `jsonld_audit.py`), not on every build. In `nowa-strona-ola` every build, including a content publish, runs a check of the built `dist` and fails before deploy.

Add one script that reads `apps/web/dist` and fails the build when an invariant breaks. A failed build keeps the previous deployment, which is the wanted outcome.

## Steps

1. Write `migration/tools/check-dist.mjs` (Node, no new dependencies if possible). For every HTML page in `dist`, except `/_ds/*` and `404`:
   - exactly one `<h1>`, a non-empty `<title>` and meta description;
   - canonical on `https://www.zawlodzki.pl`, no trailing slash, lowercase path;
   - exactly one JSON-LD script, it parses, it is a single `@graph`, and it has no `SearchAction` or `HowTo`;
   - hreflang only where both languages exist in `dist`.
2. Site-level checks: every `<loc>` in the sitemaps maps to a file in `dist`; `robots.txt` names the sitemap; every `keep` row in `migration/contracts/url-map.csv` that is a static route exists in `dist` (rows that depend on unpublished content are reported, not failed; explain the rule you chose).
3. Size budgets: report gzip size of all external CSS and all external JS. Take the current numbers, add a small margin, and fail above it. Put the limits at the top of the script with the date and the measured values.
4. Add unit tests with small fixture HTML for each failing case.
5. Wire it in: `apps/web` `build` becomes `astro build` followed by the check, so Workers Builds runs it without a dashboard change. Confirm the preview build is not affected. CI already runs `pnpm build`.

## Notes

- Do not duplicate `jsonld_audit.py` in depth. This gate is cheap and structural; the crawl diff stays the cutover gate.
- T59 (Markdown pages) is active and adds `.md` outputs. Ignore non-HTML files, and do not assert anything about them here.

## Done when

- [ ] The check passes on a build from the production dataset and the numbers are recorded.
- [ ] Each rule has a failing fixture test.
- [ ] A deliberately broken page (two `h1`, or a canonical with a trailing slash) makes `pnpm --filter web build` exit non-zero. Evidence saved.
- [ ] `tasks.py check` passes; PR opened with status `review`.
