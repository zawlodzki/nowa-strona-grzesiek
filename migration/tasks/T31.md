# T31. Homepage visual parity with the live site

## Goal

Fixes apply site-wide through shared components and sections, on every page that uses them. No route checks or homepage-only overrides.

The user reviewed the staging home page (`https://zawlodzki-web.zawlodzki.workers.dev/`) against live `https://zawlodzki.pl/` and said it is not ready to publish, mostly because of visual gaps. Fix the gaps he listed so `/` looks like live, section by section, at desktop and mobile widths. Design scope is refine, not redesign: when in doubt, match live.

## Inputs

- Live `https://zawlodzki.pl/` (HTML, CSS `zawlodzki.webflow.shared.*.min.css`, assets on `cdn.prod.website-files.com`).
- `DESIGN.md`, `migration/contracts/tokens.json`, `.claude/skills/good-css/SKILL.md`, `.claude/skills/impeccable/SKILL.md`.
- `migration/lanes/design/out/parity/report.json` (T28 parity report) for context.

## Steps

Coordinator update: all client and tool logo strips are muted (greyscale and lower opacity) by default and full colour on hover and keyboard focus. Gate hover by hover/fine-pointer media and transitions by prefers-reduced-motion. White artwork (live difference class on smmash, iimarbella, deky expo) keeps its inversion in every state; derive treatment in code, with no schema/dataset writes. Verify all other logos remain visible.

Defects reported by the user (1-10), with the likely cause found during triage:

1. **Navbar logo is not in colour.** `site/LogoMark.astro` forces `fill: currentColor` on the SVG and its paths, so the blue `#3A48CC` from `logo-mark.svg` (live `Group 4.svg`) renders in the heading colour. Keep the brand colour.
2. **"GZ" letters duplicated behind the hero photo.** `blocks/Hero.astro` renders a `.monogram` "GZ" span behind the portrait, while the hero image (live `Frame 28_compressed.webp`) already contains the letters. Remove the monogram; render the image as live does.
3. **Some client logos do not show.** All 24 logo URLs answer 200. `blocks/LogoStrip.astro` applies `filter: grayscale(1); opacity: .85` to every logo and has no equivalent of live's per-logo `mix-blend-mode: difference` (live classes `difference` on smmash, iimarbella, deky expo) and `small-logo` (`max-width: 40%`). Logos built for that blend come out invisible or near-invisible. Live shows logos in full colour, `opacity: 1`, in 128 px tall cells, `width: 75%`, `object-fit: contain`. Match it, without a dataset write (derive per-logo treatment in code if needed).
4. **"Moje usługi" navigation is completely different and too big.** Live renders four inline text links (`CRM`, `AI dla sprzedaży`, `Automatyzacja`, `Asana`, class `inline-link`, primary colour, weight 500) in one row under the intro paragraph. `blocks/ContentSection.astro` renders them as a `list` of items, each with an h3 plus a text button with an arrow and a hairline divider. Render the link-only case as a compact inline link row inside the intro; it is only an accessory.
5. **"O mnie" photo is too big for the text.** In `blocks/Feature.astro` the media column is `1fr` against `1.5fr` and the 240x448 portrait scales to fill it. Live shows the photo at roughly its natural size beside the text (and hides it on small screens, `.image-3`). Cap the portrait size to match live.
6. **Contact section shows the wrong photo.** `blocks/ContactForm.astro` renders the person's full portrait (`d519a3...-240x448`) as `.portrait` at up to 14rem. Live shows only a small profile photo (`6a0ccabcd5e70885e80931f4_Barwa_Nasycenie 1 kopiak.avif`, `max-width: 20%`) above "Bezpośredni kontakt". Use a profile photo at that size. If the asset is not in Sanity, put it under `apps/web/public/brand/` (downloaded from the live CDN, not from the inventory).
7. **Cloudflare (Turnstile) badge must not show** (contact form and newsletter). `forms/LeadForm.astro` renders a visible `cf-turnstile` widget with `data-size="flexible"`. Live has no visible badge. Keep Turnstile protection, but make it non-visible unless a challenge is needed (for example `data-appearance="interaction-only"`, or the invisible mode if the site key allows it). Do not change the site key or the Worker secret.
8. **Newsletter CTA: extra checkbox, no gradient.** `blocks/NewsletterSignup.astro` renders the "Przy okazji wyślij mi…" checkbox, which this section does not need (signing up is the whole point). Remove the visible checkbox but keep the form's payload valid for n8n (for example a hidden `newsletter=on`, check `forms.md` in verify-web and `worker/form.ts` expectations). The background is flat `--surface-dark`; live uses `linear-gradient(45deg, #0b0a47 50%, var(--primary--60))` (`c-b-gradient-dark`). Match it with tokens.
9. **h2 accent: only "Atlas" is coloured.** In `NewsletterSignup.astro` the accent span wraps only "Atlas". It is a proper name: wrap "Sales Atlas", and render live's text gradient (`gradient-secondary`: `linear-gradient(315deg, secondary-60, #fff 84%)` clipped to text).
10. **Footer is broken.** `site/Footer.astro` renders one flat row of links from `siteSettings.footer`. Live has: the colour logo, the Sales Atlas System badge (links to `/sales-atlas-system`, live asset `sales-atlas-system-pion.svg`, with its animated ring), four link columns with titles (CRM, AI, Asana, Materiały), the Pipedrive Authorized Partner badge, social icons (GitHub, LinkedIn, X), and a bottom row with "© <year> Grzegorz Zawłodzki. Wszelkie prawa zastrzeżone.", "Zarządzaj zgodami", Regulamin, Polityka prywatności. Rebuild it to match. Do not change the Studio schema or write to any dataset: derive the grouping in code from the existing links (typed constant in `site/`), and put brand assets under `apps/web/public/brand/`. Use correct `aria-label`s (live's are wrong) and correct hrefs (live's "Wdrożenie Asana" points to `/regulamin-newslettera`; use `/szkolenie-i-wdrozenie-asana`).

Also found during triage, not in the user's list (fix only if it stays inside `owns` and is small; otherwise list as a follow-up):

11. Live colours one word of each service h2 with `c-t-gradient-primary` (CRM, AI, Automatyzacje, efektywnie). Staging headings are plain strings. Needs a content or schema change, so list it as a follow-up unless it can be done without one.

Rules: no Sanity schema change, no dataset write, no deploy. If a fix truly needs one, stop at a `Contract request: ...` under Handoff and continue with the rest. Keep the other pages that use these blocks working (check `/kontakt`, `/o-mnie`, `/newsletter` and one service page for regressions).
