# T99. Pipedrive automation page diagrams in the calm scene style (problem and steps 1–4)

## Goal

Grzesiek picked `/automatyzacje-dla-pipedrive` as the next subpage. It has five scenes: the problem and one for each of the four steps of the engagement. Rebuild them in the calm style.

## Context

- This task builds on T96 (PR #107), T97 (PR #108) and T98 (PR #109), all in review. It uses the scene base, the step track, the generator header marker and `sequence.ts`. Its branch starts from the T98 branch, so merge #107, #108 and #109 first.
- Page copy:
  - Problem: salespeople retype data instead of selling. A lead waits in the inbox, and after each call the rep fills in the CRM, creates a folder, sends a confirmation and keeps the follow-up in their head. After signing, someone retypes it all again for the project, the accounting and delivery.
  - Step 1: map the flow from lead to delivery and pick the automations with the biggest effect. Do not automate a mess.
  - Step 2: build in n8n, Make or Zapier on the client's accounts and test on real data before going live.
  - Step 3: go live with the team. Everyone knows what runs automatically and what is still theirs.
  - Step 4: handover. Each flow is documented and a trained person can fix and extend the automations.

## Requirements

1. Rebuild all five scenes on `sequence.ts` (no new scene scripts), following the direction recorded in T92: hairlines and type, Polish labels, site tokens only, Signal Cyan only as decoration for automated work, calm tempo, one closing number, the problem ending in Error Red.
2. Each file carries the T96 header marker. Every scene works in the 320px slot. Bars, if any, are drawn to scale.
3. Times, names and counts are placeholders until Grzesiek confirms them.

## Handoff

### What changed

All five scenes are rebuilt on `sequence.ts`. Each carries the T96 header marker, and its only script is `import "./sequence"`. All motion is CSS transitions on `.is-done`, gated by `prefers-reduced-motion: no-preference`.

- `zw-auto-problem`: one won deal and six chores typed by hand: CRM, client folder, confirmation, follow-up reminder, delivery project, invoice data. Each row gets a red "+N min". The scene closes on "Przepisywanie na jedną szansę · 39 min" in Error Red.
- `zw-auto-map` (step 1): five steps from lead to delivery. Each gets its weekly hours as a bar drawn to scale (max 3 h) and a verdict: "automatyzujemy" (Atlas Blue on Cyan Tint, cyan bar) or "zostaje ręcznie" for the offer. The scene closes on "Wybrane automatyzacje · 4 z 5".
- `zw-auto-build` (step 2): a test record runs through Formularz → Dane firmy → CRM → Zespół on the shared step track. Each link fills with cyan, then the next ring lights up and "test OK" appears. The scene closes on "Rekordy testowe bez błędu · 24 z 24". The next-ring fill is pure CSS (`.sc-link.is-done + .sc-step .sc-ring::after`), so no scene script is needed.
- `zw-auto-golive` (step 3): two lanes, "Automatycznie" (cyan rule) and "Zespół". Five tasks land in their lane one by one, each on its own row so the order of the process stays readable. The scene closes on "Zadania z jasnym właścicielem · 5 z 5".
- `zw-auto-handoff` (step 4): four flows. Each gets its documentation marked "gotowy" and its owner switched from "Grzegorz" to "Wasz admin". The documentation column hides under 30rem. The scene closes on "Przepływy przekazane · 4 z 4".
