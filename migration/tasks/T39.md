# T39. Blog post layout parity

## Goal

Grzesiek's feedback on https://zawlodzki-web.zawlodzki.workers.dev/blog/asana-vs-jira, applying to every post (shared post template, no per-post hacks). Compare with live https://zawlodzki.pl/blog/asana-vs-jira. Sidebar and share pattern reference: https://aleksandraolesiewicz.com/blog/pcos-co-to-za-choroba/

1. Add a table of contents (generated from the post headings), in a left or sidebar column as fits the layout.
2. Add a CTA in the right column.
3. Under the post content the order is: author note, then CTA, then FAQ.
4. Fix the author section: CTA content is wrongly rendered inside it, and the photo is cropped badly.
5. Remove the "related posts" section under the post.
6. Add a "Sprawdź również" section in the right column, as on Aleksandra's blog, listing 3 related posts. These posts must be selectable in the CMS (a reference array on the post document, max 3; fallback when empty: 3 newest other posts).
7. The TOC and the right column (CTA + "Sprawdź również") are sticky while scrolling on desktop; on mobile they stack sensibly.
8. Under the TOC add a "Udostępnij" button. On click it shows share options: X (x.com), LinkedIn, Facebook, email, WhatsApp and copy link, similar to Aleksandra's blog. Accessible (keyboard, focus, aria), no third-party scripts.

Parallel task T38 owns the /blog index files (PostCards, NewsletterSignup, BlogIndexView, seo/**). Do not edit those; build post-page components under apps/web/src/components/post/. If you must touch routes.ts or site.ts queries, keep changes limited to the post query.

Schema changes go in the PR. No production Sanity writes: if content needs migrating (e.g. initial related-post references), prepare a dry-run patch script and describe it in the Handoff.

### Review feedback implemented on 2026-11-11

This review update supersedes the original full-portrait and flat-TOC behavior
recorded above. Implementation was performed directly, without child tasks.

1. The Udostępnij trigger now includes a decorative inline SVG with currentColor,
   token spacing and em sizing. Its accessible name and keyboard behavior remain.
2. The author portrait is now a fixed 80×80px circular profile crop, using cover
   and a position toward the top of the image to keep the face visible.
3. A shared typed outline derives slug IDs from heading text, normalizes Polish
   characters and disambiguates repeated titles with their block keys. PostBody
   renders those IDs on the actual h2/h3 elements and preserves inline formatting.
   PostToc nests each h3 under its preceding h2. Its small progressive script uses
   a passive scroll listener throttled by requestAnimationFrame, updates a single
   aria-current="location" link, and handles reverse scroll and hash changes.
   Server-rendered anchors and nesting work with JavaScript disabled.
