# T30. Block fields for content the page import drops

## Goal

Give the blocks fields for live content that the T16 importer has nowhere to put, so T20 can import it and pass G3. Design scope is refine, not redesign.

## Inputs

- `migration/lanes/migration/out/pages-report.json`, key `textLoss` (per page, section and block type)
- `migration/00-inventory/live-site/html/` (`index.html`, `kontakt.html`, `program-partnerski.html`, `newsletter.html`)
- `migration/lanes/seo/out/g3-staging.md` and T20 Handoff (2026-11-09)

## Steps

1. `logoStrip`: an optional tagline and intro line, as on live ("Z kim współpracuję", "Dotąd współpracowałem z firmami, które zatrudniają od 2 do 500 pracowników", "Łączę narzędzia, z których zespół już korzysta").
2. `contactForm`, `full` variant (/kontakt): optional intro ("Współpracę najlepiej zacząć od rozmowy…"), the consultation explainer, the calendar link, and the contact channels with their notes (social media, e-mail, phone, Signal, WhatsApp). The `landing` variant keeps its form and the "Bezpośredni kontakt" column.
3. A `postList` block (latest N posts of one `kind`) for the /newsletter page's list of recent issues. Render it in `PostList.astro`. T20 wires it into `lib/sanity/Sections.astro`, which T20 owns.
4. Update `blocks.json`, add a row to `decisions.md`, regenerate the types, and add the new states to the `_ds` catalog.
5. Do not change the importer or write to any dataset. T20 maps the dropped text into these fields and re-imports.

## Done when

- [ ] Each field above exists in the schema, the contract and the component, and renders in the `_ds` catalog with and without content.
- [ ] Studio and web builds, Astro checks and `tasks.py check` pass.
- [ ] Handoff lists the field names T20 must fill.
