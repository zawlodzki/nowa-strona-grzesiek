# T125. Preview Worker renders one document without loading the whole site

## Goal

Editors wait about 7 seconds for every preview in Presentation, and again after every reload. On 2026-11-20, `wrangler tail zawlodzki-web-preview` showed one render of `/blog/aplikacje-ktore-sprawdzilem-w-4-biznesach` taking about 6.3 s of wall time and 3.7 s of CPU. Fonts, CSS and scripts only start after that, so the iframe fires `load` at about 7 s. Presentation shows "Loading." until `load` fires and an error card after 15 s, so a slower page or a larger site will cross that limit.

The handshake itself works. `/api/preview` returns 307 with the session cookie, every asset returns 200, and in real Chrome visual editing connects with "Edit" on.

Likely cause, not yet measured: `loadPreviewSite` in `apps/web/src/preview/site.ts` runs the full `fetchSite` query (all pages, posts, testimonials and assets) with stega encoding on every request. `selectPreviewDocuments` and `parseSite` then process the whole site. Stega walks every string in that result.

## Requirements

1. Measure first. Split one render into Sanity query time, stega encoding, `parseSite` and HTML rendering, locally under `wrangler dev` against the `development` dataset. Record the numbers before changing code.
2. Remove the cost the measurement points at. Options, in rough order of preference:
   - Query only the requested document and what its route needs: references, navigation, settings, related posts.
   - Apply stega only to the documents shown on the page.
   - Cache data that does not change per draft, such as site settings or navigation, within the request's isolate with a short TTL. Draft content must never be cached.
3. Keep the T19 security boundary. Session or Basic Auth on every request, `private, no-store`, `noindex`, the drafts perspective, and no browser-readable token.
4. Keep the existing behaviour for incomplete documents: 422 for the selected incomplete document, while incomplete unrelated drafts are still ignored.
5. Do not change the production static build or `fetchSite` for production. Shared code in `apps/web/src/lib/sanity/` is outside this task's `owns`. If a change there is needed, write a contract request in Handoff.

## Handoff

### What changed

- `apps/web/src/preview/site.ts`: new `previewQuery(siteQuery)` and `routeDocument(href)`. The preview reader still goes through `fetchSite`, but it rewrites the production query it receives. Pages other than the route's page come back with `sections: []`. Posts other than the route's post come back with only their first body block and `faq: []`. Every other key (assets, logos, testimonials, services, courses, reusable sections, person, organization, translations) is the production query unchanged, so it stays in sync. If the production query stops selecting pages or posts in the expected form, the rewrite throws instead of silently falling back.
- `apps/web/src/preview/site.test.ts`: tests for the route-to-document mapping, including EN, the blog listing pages and `/enigma`, and for the rewrite leaving every other line of the production query unchanged.
- `migration/lanes/web/out/T125/`: `measure-data.ts`, the measurement script, and `timings.md`, the method plus before and after numbers.
- No change to `apps/web/src/lib/sanity/`, the production build, `security.ts`, `session.ts` or `selection.ts`. No contract request.

### Measurement (requirement 1)

Local data side on the public `development` dataset, median timings (details in `timings.md`):

| Route | Result | stega | select + parse |
|---|---|---|---|
| post, before | 3262 KB | 989 ms | 58 ms |
| post, after | 510 KB | 63 ms | 14 ms |
| page `/`, before | 3262 KB | 898 ms | 40 ms |
| page `/`, after | 513 KB | 76 ms | 15 ms |

Post bodies were 2.6 MB of the 3.2 MB result, and stega walked every span in them. Other posts' FAQs added 275 KB. Both are now loaded only for the route's own document.

### Deviations

- No local split of HTML render time under `wrangler dev`. It needs a draft-reading Sanity token in a local env file, and the owner chose to skip that locally (2026-11-21). For the same reason `verify-running.mjs` was not run with valid content. I did run the built preview Worker under `wrangler dev` with throwaway local credentials and an invalid token. Results: anonymous `/` 401; authorized `/` and the post 502 "Podgląd jest chwilowo niedostępny" with no upstream details; `/Uppercase` 404. Every response carried `Cache-Control: private, no-store, max-age=0` and `X-Robots-Tag: noindex, nofollow, noarchive`.
- No isolate cache for settings or navigation. After the trim, the data side is well under the CPU budget, and skipping the cache avoids any risk of serving stale drafts.

### Security boundary and incomplete documents (requirements 3, 4)

Unchanged by construction: `security.ts`, `session.ts` and `selection.ts` are untouched, and the client still uses `perspective: 'drafts'`, `useCdn: false` and a server-only token. `selectPreviewDocuments` still runs on the full list of pages and posts. A selected incomplete document still returns 422. An unrelated post with an empty body still has an empty body after the trim, so it stays excluded and never blocks a valid preview.
