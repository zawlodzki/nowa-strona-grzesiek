# T05. DNS zone file for Cloudflare import and DNSSEC sequence

## Goal

A verified zone ready to import into Cloudflare, without changing any external system.

## Inputs

- migration/00-inventory/dns/
- migration/PLAN.md section 8

## Steps

1. Add `migration/lanes/tracking/private/` to `.gitignore`. The repo is public: no record values, DKIM keys or tokens in tracked files.
2. `zone-to-bind.py` turns `zone-zawlodzki.pl.csv` into a BIND file in `private/`, without NS records and without rows marked drop or stale.
3. `dig` every record against the OVH nameservers; list mismatches by name and type in `dns-plan.md`.
4. List DNS-only vs proxied records (names only). Check `dig DS` and `dig DNSKEY`; write the exact DNSSEC disable-and-wait sequence.

## Done when

- [x] BIND file exists locally and matches dig for every kept record.
- [x] dns-plan.md has no record values.

## Handoff

**What changed.**
- `migration/tools/zone-to-bind.py` reads `00-inventory/dns/zone-zawlodzki.pl.csv` and writes `migration/lanes/tracking/private/zawlodzki.pl.zone` (gitignored). It drops NS rows and rows whose note says stale or safe/candidate to drop. `--verify` digs every kept record at `ns11.ovh.net` with recursion off and prints names, types and verdicts only.
- `migration/lanes/tracking/out/dns-plan.md` has the kept and dropped lists, the dig result, proxied vs DNS-only, the observed DNSSEC state, the disable-and-wait sequence and Cloudflare import steps.
- `.gitignore` ignores `migration/lanes/tracking/private/`.

**Deviations.**
- An RRset has one TTL, so the tool gives each RRset its lowest listed TTL. The CSV listed 86400 for one apex TXT, OVH serves 3600 for the set.
- TTL 0 (OVH zone default) is written as 3600, the TTL OVH serves for those records.

**DNSSEC is off.** On 2026-10-21 no `.pl` nameserver returns a DS for zawlodzki.pl and whois says `Unsigned`. The inventory, taken the same day, saw a DS and `Signed`. OVH still serves DNSKEY. This task changed nothing at OVH. The user confirmed they disabled DNSSEC in OVH on 2026-10-21, after the inventory. The sequence in dns-plan.md starts with a check that skips the disable step when the DS is already gone.

**Follow-ups.**
- Before the NS switch, rerun the dig check against the Cloudflare nameservers (change `OVH_NS` or add a flag).
- `named-checkzone` is not installed here, so the BIND syntax was checked by the dig round-trip and a field count, not by BIND itself. Cloudflare's import is the final parser.

**Evidence.**
- BIND file matches dig: `python3 -I migration/tools/zone-to-bind.py --verify` prints `24 kept records, 0 mismatches` and exits 0. The one extra served value is the dropped OVH marker, reported as "served at OVH, dropped by plan".
- No values in dns-plan.md: a script split every non-NS value in the CSV into tokens and searched dns-plan.md and zone-to-bind.py. No hits after removing one Webflow token. `git check-ignore` confirms the private zone file is ignored.
