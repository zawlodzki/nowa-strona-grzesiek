# T94. Add sectionRef to the blocks contract

## Goal

T54 added a `sectionRef` page block ("Sekcja wspólna") to the Studio schema and to `blockTypes`, but not to `migration/contracts/blocks.json`. `node apps/studio/scripts/verify-schema.mjs --schema-only` now fails its "page sections equal contract blocks" assertion, because the contract lacks `sectionRef`. The script is not in CI (`pnpm check`, `pnpm test` and `pnpm build` still pass). This task is the T54 contract request.

## Requirements

1. Add `sectionRef` to `migration/contracts/blocks.json` so it matches the schema in T54 (`apps/studio/schemaTypes/blocks.ts`): type `sectionRef`, a required `section` field that is a reference to a `reusableSection` document, filtered to the page's language. Give it a purpose and a component name consistent with the other blocks. It has no Webflow `match` rule (it is new, not imported).
2. Add a row to `migration/contracts/decisions.md` for the change (required by AGENTS.md for every contract edit). `decisions.md` is in `owns` only for that row.
3. `reusableSection` is a document type, not a page block. Do not add it to `blocks.json` unless `verify-schema.mjs --schema-only` still fails without it; if you do, record why in Handoff. Do not change the Studio schema, the site code, or any other contract file.
4. Run `node apps/studio/scripts/verify-schema.mjs --schema-only` and confirm it passes. Do not write to Sanity and do not deploy.

## Done when

- [ ] `node apps/studio/scripts/verify-schema.mjs --schema-only` passes locally on a clean checkout of the branch.
- [ ] `decisions.md` has a row for the change.
- [ ] `tasks.py check` passes; PR opened with status `review`. No schema or site-code change, no Sanity write.
