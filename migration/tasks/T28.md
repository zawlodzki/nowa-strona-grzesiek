# T28. Design parity against the live site

## Goal

Compare the new site with live zawlodzki.pl for every keep URL, and check the refine rules in the browser. The crawl diff stays with T20. This report sits beside it as an additional G3 check. This task does not deploy, and it does not close T20.

## Inputs

- `migration/contracts/url-map.csv`, every row with action `keep`
- `DESIGN.md`, including its frontmatter, and `migration/contracts/tokens.json`
- `migration/lanes/design/out/blocks-refine.md`
- `.claude/skills/verify-web/features/README.md` for the feature-file contract
- Live `https://www.zawlodzki.pl`, the local Worker from verify-web, and staging `https://zawlodzki-web.zawlodzki.workers.dev`

## Steps

1. Add `.claude/skills/verify-web/features/design-parity.md`. Follow the feature contract in the README. One H1, one opening paragraph, then the four H2s `Sub-features`, `How to get to it (user POV)`, `Driving it with web.sh`, and `Gotchas`. Do not edit the README. T10 owns it and is done. Do not edit `web.sh`, `crawl-diff.md`, `discovery-files.md`, or `pages.md`. T20 still owns those. The recipe starts the Worker with `web.sh`, then runs the tool from step 2.
2. Add the tool under `migration/tools/design-parity/`. On Linux, use `CHROME_BIN` when it is set, otherwise Playwright's Chromium. Do not hardcode `/Applications/Google Chrome.app`.
3. For every keep URL, capture the live page, the local Worker, and staging, at 1280 and at 375. Write a side-by-side image and a pixel or region diff for each pair. Put the report and the images in `migration/lanes/design/out/parity/`.
4. In the browser, read computed styles for each block. Compare them with `migration/contracts/tokens.json`, the DESIGN.md frontmatter, and `blocks-refine.md`. Cover at least these refine rules. Boxed surfaces use the 20px radius, and parts inside them stay at 6px. A primary button hover is a flat Atlas Blue Hover, with no live hover gradient. Links on Night Navy use Atlas Blue On Dark and meet the contrast DESIGN.md states for that pair. Section padding is 48px at 390. A difference that one of those rules explains is intended. Any other difference is a defect, with the page, the block, the viewport, and the screenshot.
5. Until T27 is done, header and footer differences are expected. List every one in the report. Do not hide them, and do not fail the run for them alone. After T27 is done, those differences are defects unless a refine rule explains them.
6. Leave `migration/PLAN.md` unchanged. The G3 sentence there still names only the crawl diff. Updating that sentence is a follow-up, because this task does not own the plan.

## Done when

- [ ] `migration/lanes/design/out/parity/` has a report that covers every keep URL at 1280 and at 375, for the live site, a Worker started with verify-web, and staging. The Handoff quotes the report path and the counts of intended refine diffs, expected header and footer diffs, and defects.
- [ ] The computed-style checks ran in a browser. The report names each refine assertion and marks it pass or defect.
- [ ] `design-parity.md` is the verify-web recipe, and `migration/tools/design-parity/` produced the report. The report is an additional G3 check beside T20's crawl diff. `migration/PLAN.md` is unchanged.
- [ ] The evidence comes from the live site, the local Worker, and staging. A build log alone does not pass.
- [ ] There was no deploy and no write to Sanity.
