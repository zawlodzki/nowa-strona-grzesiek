# T64. Sanity backup and restore procedure

## Goal

After cutover Sanity is the only copy of the site's content. This repo has no backup script and no restore instructions. Several open tasks write to the production dataset (T47, T51), and each asks for a "backup path" without a shared tool. `nowa-strona-ola` has a `backup:sanity` script and a restore document.

Add a repeatable export of the production dataset, and prove that it can be restored.

## Steps

1. Write `migration/tools/backup-sanity.mjs`: export project `8u2zjhvn`, dataset `production`, documents and assets, into a dated archive in a directory outside git. Use the official export (`sanity dataset export` or the export API); read the current Sanity docs first. Include drafts when a read token is present in the environment, and say in the output whether they were included.
2. The script verifies its own output: the archive opens, the document count matches a GROQ `count(*)`, and the asset count matches. Print a one-line summary with counts and a checksum.
3. This repo is public. Add the backup directory to `.gitignore`. Never commit an export. Nothing from the export goes into the evidence folder except counts and checksums.
4. Write `migration/lanes/cms/out/backup/RESTORE.md`: how to restore into a new dataset, how to compare it with production, how to switch the site build to it (`SANITY_DATASET`), and what a restore does not bring back (webhooks, CORS origins, tokens, Studio deployment).
5. Restore drill. Creating a dataset is an external write: ask the user first. Import the fresh export into a scratch dataset, build the site against it, compare page count and a few pages with the production build, then ask before deleting the scratch dataset.
6. Recommend a schedule and a storage place (for example a private R2 bucket, or the private inventory repo for small exports) and ask the user to choose. Implementing the schedule is a follow-up unless it fits in this session.

## Done when

- [x] One command produces a verified, dated export outside git; counts and checksum are recorded.
- [ ] `RESTORE.md` exists and was followed once end to end in the drill, with the result recorded.
- [x] `git status` shows no export files; `.gitignore` covers the backup directory.
- [x] The user's choice of schedule and storage is recorded under Handoff.
- [ ] `tasks.py check` passes; PR opened with status `review`.
